# 首发旅程PM并行派工（r08）

用户在r07完整核对后明确要求多个PM并行完成需求和Demo。本次签发首发集合J01—J11的PM工作，替代此前“不要让PM开工”的停止点；UX、RD、QA以及J12—J15仍不启动。需求范围与规划版本沿用r07，不因并行修改。

三条泳道同时进行，每个PM在自己泳道内逐旅程完成，不等待另一泳道的完整模块。本轮是纯PM产物协作，采用同一工作区中的独立目录与不重叠白名单、各自内存Demo；不启动共用业务服务、共用数据库或调钟环境，Git索引由PJ独占。后续RD仍按原方案隔离分支/worktree及运行环境。各旅程分别写`docs/product/journeys/jXX/`、`demo/journeys/jXX/`和`tests/test_pm_jXX.py`；禁止跨写其他旅程、原PRD、旧Demo及共享源码。详细白名单和实时状态见[派工数据](pm-parallel-dispatch.json)、[执行数据](journey-execution.json)。新目录的唯一产出者为所列PM；后续修订仍回该作者，PJ不代写需求/Demo。

## 每个旅程成对交付

- `requirements.zh-CN.md`：用户目标、角色/入口/前置、完整正常路径、字段校验、规则/权限/状态、失败/恢复/返回/取消、明确不做、可观察验收及未决项。
- `coverage.json`：从r07台账筛选本旅程/版本的原文ID，说明原FR/PATCH/AC等在需求章节和Demo场景的位置；共享、历史、未来、仅文档约束要明确，不能把有映射称全部可演示。
- `index.html`：自包含可交互Demo，直接打开；无需模型、真实账号、网络或环境搭建。模拟数据/角色/服务与未实现边界单独写清；产品界面保持已有Fancy方向。每个旅程各自完整，不能只交验证码、一个按钮或静态截图。
- `author-verification.zh-CN.md`及`artifact-manifest.json`：作者实际自测、原文/需求/Demo版本和哈希、已跑/未跑、模拟/真实边界。

J01包含完整注册登录、必要资料、回同一饭局及主动申请，不依赖之后再补注册。J02/J03/J04各自的AI路径不得遗漏；J05负责明确偏好及生命周期。J10首发概览仍保留既有激活/再赴约指标，J12专门页面后置不减概览范围。举报/删除/支持的受理和最终完成分开。真实外部门槛保留，Demo不冒充服务接入。

## 复核、提交与停止点

各PM运行本旅程作者验证并向PJ交付精确文件白名单，完成后停止写入；发现问题交回原作者修改。PJ负责索引、范围/版本/交叉规则复核及可打开检查，不将作者自测或PJ检查称独立QA。

共享工作区由PJ按各作者明确白名单串行原子提交、推送并核对SHA；PM不并发操作Git索引，研究/旧QA等无关改动不混入。这是本轮明确的集成交接，未改变原作者写入规则。可以先提交某旅程的完整候选，不等待所有其他旅程完成；每个旅程单独版本与候选状态。

本轮交付后停在PM候选供用户审阅，不自动进入UX、RD、QA，不把所有PM文档拼回一份巨型需求。
