## 3. 首发联调与完整MVP联调分开

| 首发联调组 | 固定候选的必要结果 |
| --- | --- |
| R-IOS-CORE | 身份/资料、创建申请审批、安排锁/截止、消息与饭后联系，从iOS正常入口跨账号完成 |
| R-ADMIN | 首发四页、分类接受/统计Ready、快照/筛选/导出在同一候选中一致，撤权/失败不读旧内容 |
| R-SUPPORT-DATA | 举报/纠错/删除传播到联系、统计及旧导出，保留J009/J011和J008的iOS/后台适用断言 |
| R-AI | 三种草稿显式转入及人工提交，F66/F68/J005适用场景与真实模型、数据、成本逐项核证 |

各组精确批次见集合数据。IOS-MIN-01需要R-IOS-CORE、R-SUPPORT-DATA和R-AI，ADMIN-MIN-01独立上线需要R-ADMIN（含撤销/下载合同验证）；iOS与后台共同开放真实用户后再核R-SUPPORT-DATA完整用户链，不能拿后台内部合同测试关闭iOS删除旅程。必要时在版本间联调，记录一组iOS build＋API/worker SHA＋数据库迁移/契约版本＋后台产物hash；联调发现问题回到对应批次作者，不另造一个能修改所有模块的集成worker。仅重跑影响范围。

I01—I04仍是完整MVP范围的检查点；首发不要求尚未纳入的分享/推送闭合I04，而使用R-AI及首发其他三组。Q-SHARE-01不阻塞本次首发，但阻塞后续完整分享。未测旧断言仍保留原状态，因平台/发布范围变化而暂不执行的部分有明确归属，不能改为PASS。

## 4. App Store适用要求核查

以下是2026-10-26读取Apple一手材料后的适用核查，不是已完成的审核结论。

| 条件 | 本项目处理 |
| --- | --- |
| 用户生成内容（UGC） | 核证发布过滤、举报及实际响应、滥用者屏蔽和公开联系信息；仅清除私聊同意不足以证明覆盖公开资料/饭局/群聊等全部风险。按1.2形成S-UGC阻塞项。 |
| 登录服务 | Google登录同时核对4.8的等效隐私选项，本项目保留既定Apple登录；不把规则表述成所有App一律必须第三方登录。 |
| AI个人数据 | 在分享给第三方AI前说明接收者与用途并取得明确许可，拒绝时保留普通业务；现有说明文字不自动等于实际许可流程。记S-AI-CONSENT。 |
| 完整性 | 真机、可用后端、审核访问及真实元数据准备完成再提交，不以模拟/占位/死链接送审。记S-STORE-PACKAGE。 |

来源：[Apple App Review Guidelines：1.2、2.1、4.8、5.1.2(i)](https://developer.apple.com/app-store/review/guidelines/)。上表为适用规则的归纳；实际产品如何覆盖须由PM/UX/RD/QA逐批核证，不扩建通用安全后台。

账号删除应能在App内发起，完成后按要求处理关联内容，Apple身份撤销需真实验证；不能只停用账号或让普通用户必须邮件申请删除。现有M07-04/05保留同步屏障、异步处理/回执，以及Apple撤销门槛。来源：[Apple账号删除说明](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)。

隐私政策有效URL及App Store Connect数据处理披露需与实际接入一致，包括第三方SDK/模型；政策仍为草稿时不可冒称已满足。来源：[Apple管理App隐私](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)。发布所需隐私/支持静态页面不等于重启移动Web业务前台；它们仅承载法定/审核与支持信息，无发现/申请/聊天功能。

提交时还需按当时App Store Connect核对开发者资格、Bundle ID/签名与适用SDK、截图/图标/描述、年龄分级/地区、审核说明、出口合规及相关隐私清单。18+业务门槛不直接替代商店分级问卷。具体账号/构建与提交项待核，绝不预写“已经可上架”。来源：[Apple审核准备](https://developer.apple.com/app-store/review/)。

## 5. 未闭门槛与发现缺口的处理

现有AUTH/PLACES/MAIL/IOS/PRIVACY/HOST/AI-MODEL/DATA/COST按首发范围保留；后台另核内部身份/最小权限、真实采集与快照口径、撤销导出、恢复/负载和监控。已有账号或本地测试不替代真实服务证据。

新增S-UGC、S-AI-CONSENT、S-STORE-PACKAGE均为not-verified且阻塞iOS提交。缺口表位于集合数据，具体缺口若需代码/交互修改，先形成一个小的纠偏工作包，独立完成PM、UX、RD、QA后再记关闭，不把它夹入任意普通批次或用平台审批替代实现。当前没有签发这些纠偏任务。

发布前必须同时满足：集合闭包适用批次已验收、首发联调组通过、发布门槛逐项有证据、产品界面和审核材料与集合一致、最终明确发布授权。当前没有满足这些条件的宣称，没有App Store提交或后台部署。
