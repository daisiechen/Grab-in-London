# Fancy 全流程审查与修复记录

日期：2026-10-18｜对应 PRD：v0.4｜范围：现有17个应用路由及6个品牌/账号步骤。以本轮实际浏览器观察、截图、交互和代码核对为依据。目标是清理产品界面的实现备注、统一现有样式并排除核心流程断点，不扩展真实后端。

## 审查路径与结果

| 步骤 | 页面 / 路径 | 本轮观察与操作 | 结果 |
| --- | --- | --- | --- |
| 1 | 开屏、欢迎 | 字标、邀请语、自动结束/重播、游客入口 | 正常；默认没有原型横幅、城市边注和 Replay |
| 2 | 账号入口 | 注册/登录选择、Google/Apple占位弹层、取消、隐私说明 | 正常；不是实际OAuth |
| 3 | 邮箱、验证码 | 邮箱输入、错误码、有效码、进入补资料或恢复受限目标 | 修复报错里的 demo code；错误后收起键盘，避免错误藏在键盘后 |
| 4 | 注册资料 | 姓名、20字以上介绍、兴趣语言、年龄确认、完成注册 | 正常；仍是本地前端账号 |
| 5 | Discover 地图 | 切换区域、Soho上一/下一饭局、区域全部列表、卡片打开详情 | 正常；图钉数量是饭局数量 |
| 6 | 列表与筛选 | 地图/列表切换、日期独立弹层、双人筛选、全部筛选、无结果后Clear | 正常；筛选草稿与已应用结果分离 |
| 7 | 饭局详情 | 餐厅、费用、状态、参与者头像、Google Maps区域链接 | 修复固定套餐的重复价格区间；保留真实区域链接，不编造餐厅地址 |
| 8 | 成员与自己主页 | Maya/Emma主页、屏蔽、自己的头像、编辑姓名后保存 | 修复自己的头像指向旧资料、成员参考评价署名和空工作行 |
| 9 | 加入申请 | 申请→待审批→Inbox；拒绝→发现；撤回→重新申请 | 正常；已提交后回到申请表提供 View application，避免重复提交 |
| 10 | 支付确认 | 审批后支付、失败提示、恢复成功 | 修复付款直接确认餐厅的错误；保留餐厅原状态；整场取消不允许支付 |
| 11 | 预约与发起人 | 发布→审批线下付客人→确认2人预约→群聊 | 正常；发起人可从预约页直接进群；仅发起人可调整整桌预约，人数改变可更新预约人数 |
| 12 | 取消、退款 | 预约失败后全额退款说明、退出、退款金额、取消分类 | 修复退出时误取消整场预约、退款金额随其他场景变化、取消饭局混入Upcoming |
| 13 | 群聊 / Inbox | 待审批锁定、待付锁定、确认后可发消息、餐厅失败仍可讨论 | 正常；取消后仅历史成员可查看归档，无消息输入和发送按钮 |
| 14 | Create：Arrange | 餐厅、2–6人、日期、无时段恢复、月边界、时间选择 | 正常；可用时段外不能继续，创建日历停止翻入无库存月份 |
| 15 | Create：Introduce | 标题、介绍、氛围、语言、前后步骤保留草稿 | 正常；键盘输入后可前进 |
| 16 | Create：Costs | 现场付、订金、固定套餐、外订未确认拦截 | 修复费用小数精度与套餐/现场付说明；外订确认必须匹配当前安排 |
| 17 | Create：Review | 审阅、分组编辑、条款确认、发布详情 | 正常；新饭局携带菜系、饮食选项和区域坐标 |
| 18 | Meals | Upcoming / Applications / Hosting / Past / Cancelled | 修复分类；空态可返回发现，Cancelled保留记录 |
| 19 | 餐后评价 | 参考评价、私下再次见面意愿、保存、等待双方提交 | 正常；餐后入口带入实际饭局/对象，公开参考与私密反馈分开 |
| 20 | 私聊 | 双方同意后开放、发送消息、Inbox入口 | 正常；消息按对象分开保存；普通模式没有制造对方同意的按钮 |
| 21 | 设置 / 举报 | 消息预览开关、屏蔽Emma后Maya不受影响、解除、反馈提交 | 正常；设置显示实际被屏蔽的成员，举报仍为前端提交占位 |
| 22 | 退出 / 验收工具 | 退出确认→账号页；重播保留会话；重置清除状态 | 正常；验收工具只在review模式出现 |
| 23 | iPhone / Pixel | 欢迎、表单、创建审阅、资料保存、设置、退出 | 未观察到文字溢出或设备框破坏；统一返回命中区、外链焦点与提示层交互 |

## 修复清单

| 编号 | 发现 | 修复 |

| F01 | 验证码错误仍提示Use the demo code | 错误/过期使用产品语言；固定测试码仅在开发文档保留 |
| F02 | Inbox待付款和预约页遗漏No real...说明 | 从默认产品文案移除，模拟边界记录在PRD与验收模式 |
| F03 | 支付成功把餐厅改为CONFIRMED | 独立处理席位支付与预约；取消饭局禁止支付 |
| F04 | 访客可自行改整桌时间；预约失败群聊入口消失 | 预约操作限发起人，确认成员保留群聊；发起人预约页补群聊入口 |
| F05 | 一个blocked布尔值影响所有成员 | 按memberId保存屏蔽与解除，私聊按实际对象判断 |
| F06 | 自己头像打开固定示例资料 | 打开当前个人主页；姓名随编辑更新，空工作字段不渲染 |
| F07 | 退出会改整场预约；退款金额读全局开关 | 退出只释放本人席位；取消时把退款金额按mealId保存 |
| F08 | 已取消参与显示withdrawn并混入Upcoming | 取消文案独立，新增Cancelled分类，选中分类可访问性状态明确 |
| F09 | 新建饭局缺少菜系/饮食属性，地图坐标固定 | 发布时从所选餐厅/区域补全筛选与定位元数据 |
| F10 | 固定套餐仍提示付余额、£0 after approval、£25–25 | 区分套餐额外费用和现场付、单一价格；金额最多2位小数 |
| F11 | 餐后入口固定显示旧饭局/Maya；私聊共用消息桶 | 带入实际饭局和对象，按联系人保存私聊；示例评价作者不自评 |
| F12 | 创建日历可一直翻到无库存月份 | 限定当前样例可用月份，提供无时段恢复提示 |
| F13 | 工具栏返回命中区小，外链焦点不统一 | 44px返回命中区、外链可见焦点；输入错误收起键盘 |
| F14 | 状态提示层遮挡操作并跨页保留旧提示 | 提示层不截获点击，导航清除旧提示，保留role=status播报 |

## 验证与限制

- 34项领域/呈现状态测试、6项Sites打包测试、17项仓库文档/业务验证通过；TypeScript与构建通过，28个受保护运行时文件校验通过。控制台检查未发现应用错误。
- 浏览器使用普通URL与 `?review=1`；外部审批、失败支付、餐厅失败、双方意愿由验收控件驱动，再检查产品页状态。没有真实扣款、邮件、餐厅预订或举报投递。
- 对会自动滚入视野的长表单控件，部分浏览器验收使用键盘Enter激活，同时检查实际目标页面和状态；不把这些结果声明为所有触摸手势、所有设备系统版本均已穷尽验证。
- 此轮未做完整读屏/对比度认证、性能专项、并发名额和多用户实时服务测试。构建主包约560KB有体积提示，非本轮功能失败。
- 真实上线仍需服务端权限、并发名额/占位过期、支付与退款回调、实时消息、餐厅库存、隐私及举报运营；这些限制在PRD保持可见，不塞入正常产品界面。
