## 补充（2026-10-22 晚，供 Codex QA 复核会话与开发协调）

### 原库恢复的连续性限制（已按源码更正；恢复是新进程，不是原样 RAM 恢复）

只读核实的源码路径与影响：

- 会话验证不依赖 `SESSION_SECRET`：数据库只存令牌 SHA-256；`authenticateToken` 按 `sha256Hex(token)` 查 `sessions`，同时要求会话族未撤销、`expires_at`/绝对过期/Web 空闲 7 天未到、用户 ACTIVE（`apps/api/src/identity/sessions.ts`）。因此换新密钥本身不会使原 Web 4 / iOS 2 个会话失效，也不能宣称它们已被撤销；是否仍有效取决于库内状态与测试钟（iOS 访问令牌 15 分钟，按测试钟计；刷新令牌 30 天可轮换）。
- Web CSRF 依赖密钥：`csrfTokenFor = HMAC(secret, "csrf:"+sessionId)`，每个 Web cookie 非 GET 请求都校验（`apps/api/src/http/routes.ts` preflight → `assertCsrf`）。浏览器内存里旧 CSRF 令牌在新进程下不匹配，首个写请求得到 403“Your session needs to be refreshed. Please reload and try again.”；重新加载页面后 `getSession` 返回新 CSRF 令牌，无需重新登录。iOS 使用 Bearer，不涉及 CSRF。
- 其他依赖密钥的派生值不连续：OTP 邮箱/IP 键控哈希（重发节流与认证事务按新哈希计算）、管理端与地点搜索游标（旧游标解码失败）、AI 游客与分析游客 cookie 作用域、删除回执 IP 限速键。
- 纯内存状态不连续：OTP 一次读通道、导出 CSV 缓冲（旧票据不可读）、助手进程内会话（旧 AI 会话按契约 410 保未发字）。
- 数据库内状态连续：业务表、`api_rate_limits` 窗口、幂等表、AI 账本（UNKNOWN 3024；D22/M10 used 3712、calls 30）、测试钟 02:01Z；D23 预算行不存在、不自动创建。
