# Agent 协作与配置边界

## 共同真源

所有 Agent 使用同一工作区和 Git 历史。项目共同规则在 [AGENTS.md](../AGENTS.md)，Claude 入口在 [CLAUDE.md](../CLAUDE.md)。[文档索引](README.md)指向主 PRD、模块需求、研究、设计及验证记录；按任务读取现有原文，不另建 Claude 专属业务副本。

项目已批准技能保存在 `.agents/skills/`，`.claude/skills/` 通过仓库内相对符号链接提供发现入口。待审核候选不进入发现目录。新增或删除正式技能时同步链接并运行配置测试。链接以 Git 符号链接保存，克隆环境必须支持符号链接。

## 可见评审流程

用户指定通过 Claude 桌面端 Code 页面调用，不安装 CLI。选择 Local 和本项目，保持会话可见。每次交接说明目标、文档路径、当前提交、未提交改动、允许修改范围和预期输出；Claude 回复及后续追问保留在桌面会话中。

需求评审默认只读。Claude 输出问题、证据路径、影响、建议和待用户决定项；Codex 核对证据后整理结论。分歧明确保留，由用户裁定。评审结论写回对应需求或决策文档；原始会话不自动上传公开仓库。

## 并发与交付

开始前检查 Git 状态、分支、远程和最新更新。共享目录中的未提交内容属于实时工作区，不等同于 GitHub 已发布版本。读取时说明使用哪个版本，不覆盖、不暂存、不回滚其他任务改动。同一文件同一时间由一个 Agent 负责修改；需要交接时先停止写入，再交代变更和验证状态。

负责修改的一方执行适用测试，仅暂存本轮文件或明确属于本轮的片段，审查后提交并推送跟踪分支，获取远程并核对 SHA。只读评审不创建空提交。其他任务尚未完成的业务变更不混入配置提交。认证、网络或验证失败应报告实际状态。

## 个人环境与公开仓库

项目共同规则、可公开文档、Claude 引用入口及技能相对链接进入项目 GitHub。个人全局规则分别从 `~/.codex/AGENTS.md` 和 `~/.claude/CLAUDE.md` 加载；个人通用技能权威源为 `~/.agents/skills/`，工具入口按各自机制配置。

个人配置由既有私有配置仓库白名单备份，项目无需包含用户绝对路径、个人规则副本或插件缓存。凭据、权限本地配置、聊天、自动记忆、缓存、worktree 和构建产物不进入公开仓库。工具系统内置规则不能通过项目文件改写；共同要求在各工具权限范围内执行，冲突时说明并暂停相关动作。

## 配置验收

静态验证入口：`python3 -m unittest discover -s tests -v`，以及 `git diff --check`。静态通过只证明入口和引用存在；还需在桌面 Code 会话中实际确认工作目录、加载规则、技能及只读访问，才能宣称 Claude 配置可用。
