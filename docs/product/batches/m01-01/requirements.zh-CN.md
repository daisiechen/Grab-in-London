# M01-01 访客入口与邮箱登录需求

修订：PM-r01｜平台：iOS App｜状态：需求与交互Demo候选，供用户审阅；未获产品批准。

对应演示：[打开M01-01 Demo](../../../../demo/batches/m01-01/index.html)。演示用静态页面表达iOS流程，能直接打开；不是真实iOS应用、移动Web产品或已接入的认证服务。

## 1. 为什么需要、谁使用

想与陌生人吃饭认识朋友的用户，应该先有机会了解Fancy和公开饭局；决定参与后，再通过邮箱证明本人身份。不应为了先看看就被要求注册，也不应以登录成功代替申请、发布或发消息。

本批面向访客、已有邮箱账号的人及首次用邮箱进入的人。首次账号完成邮箱验证后仍可能缺少参与必需的公开资料；填写资料属于M01-04，不在本批实现。已有完整资料的人也必须回到原来的业务入口，再决定是否继续操作。

目标结果：用户能选择先浏览，或通过邮箱验证码登录；取消、填错、过期或服务失败时知道如何恢复。来源意图保持，认证本身不产生业务提交。

## 2. 本批做什么、不做什么

| 本批包含 | 不包含 |
| --- | --- |
| 欢迎页、先浏览、邮箱输入和验证码输入 | Google/Apple登录、首次资料表单、资料编辑/设置/删除 |
| 请求、重发、改邮箱、取消、错误/过期/冷却恢复 | 发现地图/列表/饭局详情实际内容、创建/申请/聊天实际功能 |
| 主动登录默认Discover；业务来源登录保留原目的地 | 自动申请/批准/发布/发送，自动合并同邮箱身份 |
| 验证成功后区别资料完整与资料尚缺的后续边界 | 真实邮件/账号、服务端鉴权、原生iOS构建、Figma高保真或正式发布 |

未包含的页面只以明确的演示终点表达，不用一张假的饭局或资料表单将相邻模块提前实现。

## 3. 用户自然流程

### A. 访客先看看

1. 打开欢迎页，读到Fancy与“Meet new people over a meal.”。
2. 选择“Explore tables first”，以访客进入发现入口，不先索取定位、联系人或系统通知权限。
3. 本批Demo在Discover交接终点停止；后续M02负责实际发现体验。

### B. 主动使用邮箱登录

1. 选择“Continue with email”，进入邮箱输入页；此时仍可取消。
2. 输入邮箱，明确提交“Send code”；非法格式就地说明，不进入验证成功状态。
3. 请求成功后在验证码页看到目标邮箱，输入6位数字；可以更换邮箱或在冷却结束后重发。
4. 验证成功时说明已登录/邮箱已验证，但不显示“已加入饭局”。
5. 资料完整的账号可回Discover；首次账号停在“需要完成公开介绍”的边界，保留原来源，等待M01-04接续。

### C. 从某场饭局进入登录

1. 原入口提交返回意图，包含受控场景及同一饭局标识，不把它作为业务权限。Demo使用`meal`类型与合成mealId `11111111-1111-4111-8111-111111111111`；不是任意返回URL，也不接受外部跳转。取消、失败、重发及成功均保持这对标识。
2. 用户走相同的邮箱流程；取消认证时回原场景，仍为访客。
3. 验证成功且资料完整时回同一饭局入口，原待操作内容不被清除，不自动申请。
4. 资料不完整时先指向资料门槛，原饭局意图继续保留；本批不承诺资料补完后的整条申请已经验证。

## 4. 输入、状态和恢复规则

| 项目 | 有效规则与用户反馈 |
| --- | --- |
| 邮箱 | 去首尾空白、格式校验；错误保留输入。真实产品不通过不同提示公开探测邮箱是否注册，不收密码。 |
| 验证码 | 6位数字；错误保留邮箱并允许修正；未成功不能当作已登录。 |
| 有效期 | 自签发起5分钟；恰好达到5分钟即过期，提示重新请求，不悄悄当作成功。 |
| 重发 | 30秒冷却，冷却内不可再次请求；结束后本人主动重发，生成新一轮有效期，旧轮次失效。 |
| 更换邮箱 | 回邮箱页保留地址供修改，清旧验证码输入/挑战；新邮箱需重新请求，不沿用旧证明。 |
| 请求失败 | 停在原输入上下文，说明未能请求/重发并可重试，不提示邮件已发出。 |
| 验证服务失败 | 保留邮箱和已输入文字，允许重试，不显示账号已登录或业务已完成。 |
| 取消 | 无论在邮箱还是验证码页，都不产生认证成功；回原场景，不执行原业务意图。 |
| 成功 | 身份结果与资料完整性分开；本人决定回原入口或先补资料，后续业务仍重新鉴权并由本人提交。 |

真实产品的处理中/重复点击抑制、一次性消费、频控、响应丢失与会话安全由后续研发按既有身份合同实现；本批Demo为即时本地模拟，不提供网络并发或真实身份安全证据。模拟无需冒充这些能力已经实现。

## 5. Demo如何表达与使用

手机画面内用英文呈现拟定用户路径；画面外中文区域说明批次与模拟边界，不把演示工具做成真实产品功能。

默认“主动登录、资料完整”。展开“演示控制与边界”可选“饭局触发”或“首次账号”，点击重新开始后生效。邮箱只接受`@example.test`合成地址；这项限制只适用于演示，真实产品仍支持有效本人邮箱。

模拟验证码初始为`123456`，重发后更新，控制区显示当前合成码，画面外状态行显示来源类型及合成mealId，便于核对实际保留的标识，不只看“同一场饭局”文案。用“推进30秒/5分钟”验证冷却和过期，用“下次请求失败/下次验证失败”观察输入保留与恢复。时钟只影响此页，不触及任何真实测试现场。演示中的访客、资料和饭局终点均标“Preview boundary”。

刷新即清空，无本地持久化、真实发信、供应方调用、账号创建或申请/席位/饭局/消息写入。已有账号/首次账号也是明确选择的合成状态，不由邮箱探测得出。
