# Fancy 首期产品数据后台 PRD

版本：1.3｜定义版本：r1-v3｜日期：2026-10-19｜目标：正式开发前置规格与可交互验收原型。**真实采集及生产服务待建设**。共享业务需求以[主PRD](../PRD.zh-CN.md)及已确认D-01至D-15决定（含最终D-09至D-15补充）为准；后台原始数据、计算和接口见[采集契约](measurement-contract.zh-CN.md)。早期带平台收费/代订、人工出席核实的截图和交付记录为历史版本，不能作为R1需求。

## 1. 首期范围与使用者

内部创始人使用桌面Web分析伦敦试点，用户端目标为iOS App及移动Web；当前网页原型不代表iOS已实现。后台维持五个页面：概览、用户旅程、饭局与供需、体验与留存、数据与定义。中英切换，时间Europe/London、GBP。保留390px有效回归，以便窄窗口查阅。

不建设商家/场地、订单财务、客服工单、增长活动、员工账号管理或日常人工运营流程。首期各自到店付款，host自行外订，不收款、不平台代订。身份复用用户端既有登录，**服务端按稳定userId校验创始人白名单**；不按邮箱、OAuth显示名或浏览器字段授权。Facebook无邮箱、Apple私有中继均不改变权限主键。

### 1.1 日常判断与观测层级

| 决策 | 结果与诊断 | 后续动作/边界 |
|---|---|---|
| 真实见面是否增加 | 每周确认出席用户数；出席结果覆盖/来源差异 | 先看覆盖再判断；未报告不是未出席 |
| 需求在哪一步受阻 | 发现无结果、曝光/详情、7天申请；申请→批准→席位确认 | 区分浏览标识与申请记录；空采集源不可作0使用 |
| 为什么没约成 | 招募历史峰值、T-15分钟检查、取消原因、待审与过期申请 | 检查点是真实业务事实，不以当前峰值推断历史检查 |
| 是否兑现及愿意再来 | 首次申请后14天内出席、30天再赴约、评分与原因 | 未成熟不算流失；当前UI称“未观察满窗口”；没有完整历史只称可观测首次 |
| 是否需要个案处理 | 自助举报回执及按需状态 | 不做自动裁决、不承诺人工SLA、不靠人工核实出席 |

没有经营分析Agent、每周自动议题、自动因果解释或未经基线验证的业务达标线。系统显示确定性数据检查，创始人按需复核，不要求全职维护。

## 2. 资源、权限与审计（R-13）

| 资源/动作 | 未登录 | 已登录非白名单 | 白名单创始人 |
|---|---|---|---|
| 聚合、下钻、字典、快照列表 | 401 | 403 | 读取授权范围 |
| 聚合CSV | 401 | 403 | 绑定snapshotId+筛选+定义版本导出；不导出原始人次/消息/私密互选 |
| 统计账号分类 | 401 | 403 | 正式/测试/员工统计标签；不是创建或管理员工账号 |
| 生成快照/查看历史 | 401 | 403 | 生成请求、历史只读；不能改历史内容冒充原ID |
| 个案状态/依据 | 401 | 403 | 按需查看最低字段和处理；不用于分析模型输入 |
| 审计 | 401 | 403 | 读取分页的actor/action/subject/from/to/reason/version/time |
| 出席人工核实、verified覆盖 | 不提供 | 不提供 | **不提供** |

权限必须逐请求在服务端检查，包括导出下载地址和异步作业结果；不能只隐藏按钮。撤销白名单/会话失效后停止新请求，清除页面数据，旧深链也无权。Demo仅有虚构创始人/非白名单状态门禁，sessionStorage可被本地修改，静态bundle含虚构fixture，**不是生产鉴权**。

### 2.1 统计账号分类

数据页输入userId、目标regular/test/staff、1–200字符理由、expectedVersion，调用分类命令。测试/员工行为、申请、参与及反馈从分析中排除，其host场次整场排除。开始前招募峰值可按统计范围重算；T-15检查结果保留当时业务事实，不因事后分类伪造“当时取消”。对账用当时真实占位记录，统计范围与业务履约事实并列解释。

- 保存成功返回分类version、factVersion及auditId；不静默改变当前快照。显示待生成/待重算，明确下一步。
- 必填/枚举错误422，目标不存在404；权限403不落审计业务变更、不改数据。相同幂等意图重试返回同回执；换理由或目标是新意图。
- 409展示当前版本，保留输入与理由，用户重新读取并复核后显式重试；不自动覆盖他人改动。
- 审计追加原/新分类、稳定操作者ID、服务端时间和理由；服务端版本区分同毫秒写入。理由不填联系方式、消息正文等个人信息。
- 导入App验收JSON保留已有人工分类版本/理由；新userId默认为regular，导入users仅允许id/joinedAt且拒绝accountType，绝不静默把test/staff改regular。

### 2.2 最小按需个案回执（R-11）

App自助提交由举报服务持久化并自动返回caseId与received；用户可查询自己caseId的受理状态。后台在数据页展示按需个案编号、对象ID、原因**类别**、时间、版本与处理依据，状态received→in_progress→resolved。每次变更必须依据与expectedVersion，追加审计；resolved不重开，可重新提交新案并关联原案。没有自动处罚、公开失约榜或人工处理时限承诺。

后台展示可回传给用户的最低状态与必要结果说明，内部依据默认仅创始人可见；原始举报正文为独立授权存储，不进入分析、CSV、JSON业务投影或自动总结。Demo队列是固定虚构个案，演示回执与版本转换；App举报接收/通知与后台真实队列服务尚未连通，不能称跨端处置已上线。

## 3. 页面与交互

导航无空工作区、虚构头像、无对应页面的面包屑。品牌与导航间48px留白。常规分析页不重复演示备注；来源真实性、会话保存边界集中在数据页/文档。所有页面支持加载、空、未接入、403、版本409、失败重试与历史快照不可用，不能以旧数据伪装新结果。

### 3.1 筛选、下钻与数据单位

- 日期草稿点击应用才生效，快捷7/28/90天相对**所选快照截止时间**；无效或超出asOf日期保留旧图并提示。日/周为伦敦时间，观察期按连续UTC时长。
- 区域、来源、用户分群、语言、人数、预算均支持多选；同字段OR、跨字段AND、空选=全部。更多筛选外点/Escape/切页收起，内部可连续选，隐藏条件用数量与可移除标签表示。
- 语言按支持语言匹配，双语命中两种但并集去重；总人数含host，首期2–6。预算必填来自App人均上限，不是平台应收。区间[0,20]、(20,30]、(30,40]、(40,+∞)，未填写只为历史兼容。筛选7+只兼容旧数据，不允许R1发布7人。
- 请求可能宽范围或字段未知，不能把任意返回饭局属性补给请求；规则及手算用例见采集契约§4。筛选日期是事件发生期/业务入组期，不是请求想吃饭的日期。
- 申请记录按applicationId看每一轮，参与人次按(userId,mealId)去重；默认最新日期排序，搜索/分页/语言切换不改变统计分母。过期、撤回、被拒和确认分开，过期不计仍待审。
- 用户/饭局/队列详情可返回上一层；关闭/Escape回到触发器。队列日期打开该组全部用户。历史来源、匿名身份、未知字段和分母可追溯。

### 3.2 五页职责

| 页面 | 内容/可操作路径 |
|---|---|
| 概览 | 每周确认出席、14天首次申请兑现、30天再赴约；覆盖、来源差异、确定性检查；指标定义与证据下钻 |
| 用户旅程 | 浏览身份概览、按申请轮次的批准/确认/退出/过期、P50/P90和当前等待；发起attempt漏斗；未接行为源用未接入态 |
| 饭局与供需 | 无结果、招募历史峰值、取消原因、T-15检查及检查后低人数决定；出席present/absent/unknown分布与只读来源 |
| 体验与留存 | 可观测首次队列、观察中、跨场重复与机会曝光；反馈覆盖、1–5分、显式again、可选多原因按评分切片 |
| 数据与定义 | sourceStatus/asOf、质量、分类/审计、按需个案；显式review模式才能看到验收场景与脱敏JSON导入 |

### 3.3 出席与阶段观察（R-08/15）

应确认资格来自饭局开始时名单：未取消、host或开始前已确认且退出时间**严格晚于**startsAt（在startsAt退出也不计）。多轮申请找有效确认区间，不只拿第一轮。窗口为scheduledEndAt（默认startsAt+2h）起，至scheduledEndAt+7天之前；本人/host可提交修改各自来源。本人最新自报优先，host仅补缺，差异保留但不作为待人工任务。未知不当未出席，不提供verified字段或核实入口。

本人改absent后，不符合present资格的评分从统计移出；原记录保留用于版本追溯。后台不修改互选/聊天授权，用户端服务按同一出席事实、双向同意和拉黑规则判断。无公评R1，不将单方互选当again。

**申请→出席的阶段观察采用startsAt+24h，不是结束后24h。** 恰好24h进入阶段；窗口仍可开放到结束后7天，新快照可回补。24h统计不是最终失约或全体最终结果，页面显示仍可报告的申请数。

## 4. 不可变快照与导出（R-14）

写命令更新当前事实并返回factVersion；所选快照不变。生产小时作业或授权生成请求创建新snapshotId，返回pending/ready/failed；未ready时继续看原快照并提示，不把待重算数据混入旧下钻。Demo“生成并查看新快照”为同步内存演示，显式操作后才切换。

- 每份快照绑定asOf、definitionVersion、factVersion、源状态和独立冻结的数据副本。后续分类、导入或回补不改变旧ID内容。
- 页面、字典解释、详情、队列、列表cursor及CSV必须绑定同一snapshotId、筛选、定义版本和权限范围；切换清空旧详情和游标。历史截止更早时显式把所选结束日期收敛到历史asOf。
- 新快照就绪提示，用户明确切换；历史可选只读。相同快照+筛选+定义版本重复导出相同数值，不导出当前draft事实。CSV标snapshotId/asOf/definitionVersion/factVersion/sourceStatus、单位及分子分母，防表格公式注入。
- 生产保留期/账号删除后的隐私例外见采集契约§7；已撤销/过期ID返回410，不以别的快照替代。Demo刷新丢失内存快照，旧ID显示不可用并提供显式返回初始快照，不静默回退。
- 加载失败保留所选ID，不把上次成功结果当作新版本；权限失效不继续展示旧数据。快照URL是定位参数，不是访问令牌。

## 5. 采集、共享契约与导入（R-16/17）

指标公式、原始数据、口径与映射以[采集契约](measurement-contract.zh-CN.md)为研发附录。生产需要客户端采集、权威业务表、本人/host报告与快照管道；fixture中的production只是演示统计范围，不是真实生产数据。

App验收使用`shared/pilot.ts::projectAnalytics(s)`输出，后台只在`?review=1`开放JSON导入。严格校验r1-1、demo:true、≤512KiB、允许字段、数组上限、唯一ID/关联、UTC时间、截止、版本/枚举及资格；拒绝messages、reports正文、reconnect、verified等字段，生产数据不可导入此静态原型。错误不更新store、不生成快照、不改选中ID；成功导入生成新快照，保留旧快照与审计。空events标行为源not_connected，不能显示0使用或补fixture；业务事实仍可独立分析。未声明历史覆盖时所有“首次”仅为可观测首次。

## 6. 接口、非功能与开发边界

详见采集契约§6。主路径是创建/审核/外订/取消/出席/反馈权威服务→业务事件或增量查询→统一快照→后台；业务成功不能由客户端按钮埋点冒充。首期不要求微服务部署，模块边界不是进程边界。

- 面向当前及前一个主版本的桌面Chrome/Edge/Firefox/Safari；390px保留响应回归。实际本轮只证明记录的内置浏览器路径，不声称已完成全浏览器/读屏矩阵。
- 语义标签、键盘可达、原生对话框焦点恢复、状态消息可读；字段错误关联输入。生产目标WCAG2.2 AA须完整人工/自动验收后声明，当前无全面合规保证。
- 查询分页最多200条、opaque cursor绑定snapshot/filters/scope；无权限、失效cursor、冲突和重试均明确。快照job失败不破坏当前已ready快照。
- 分析事件原始90天，业务/审计暂定12个月，删除账号去标识和服务控制历史处理见契约；最终法律政策另审，不能以本PRD宣称法律合规。
