# Fancy按用户操作旅程划分的模块需求

需求修订：r06｜iOS与管理后台｜当前是重拆方案，尚未启动新的PM需求或Demo。

模块由用户想办成的一件事定义，从触发到可观察结果结束。登录、注册、补资料是参与旅程的必要步骤；后台页面、通知权限和统计刷新也是途经环节，不再各自变成半成品交付。真实业务仍按原PRD/补丁及采集契约执行，不新增平台支付/订位或放宽权限。

首发iOS包括J01—J08及支持运营J09，首发管理后台包括J10/J11；J12—J15是后续增量，移动Web继续后置。AI查询和三类草稿分别融入J01/J02/J03的辅助路径，不是另一个孤立模块；手动操作始终可用。

## J01 找到并申请一场合适的饭局

使用者：想参加聚餐的访客、新用户或已有用户

触发：想找一顿合适的饭，或打开某场饭局入口。

1. 浏览地图/列表，筛选并查看饭局详情、发起人公开介绍和参加条件。
2. 需要帮助时可用AI查找/比较或起草介绍，也可全程手动操作。
3. 主动申请时若未登录，在原意图中完成注册或登录；新用户完成验证码/供应方验证、必要公开资料及年龄/社区确认，已有用户不重复填资料。
4. 回到同一饭局，核对最新名额/截止、修改申请介绍并主动提交。
5. 看到申请已受理、待发起人审核及后续查看入口；等待期间可撤回，符合规则时可重新提交。

- 完成终点：申请有唯一可追踪结果，用户知道是否仍在待审；注册、登录和资料是途经步骤，不能只交付这些步骤就称本旅程完成。
- 必要异常与退出：先浏览不强迫注册；邮箱/Google/Apple取消与失败、验证码重发/过期、资料保存失败、返回/取消、满员/截止/重复或未知提交均有可恢复路径且保留适用输入。
- 不做：发起饭局、替发起人审批、自动申请/付款/占位、资料设置全模块与私聊。
- 关联旅程：J02、J03、J05，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J02 发起饭局并完成招募管理

使用者：愿意组织一顿饭的发起人

触发：准备发布一场聚餐并决定哪些申请者参加。

1. 从创建入口进入，必要时在原流程完成登录/注册和资料门槛。
2. 确认餐厅、伦敦日期时间、人数区间/截止、介绍和预计预算，核对外订声明；可用AI起草但本人确认。
3. Review后主动发布可申请饭局，不产生平台订位或收款。
4. 查看申请人公开介绍，批准或拒绝，知道已确认成员、剩余名额与声明是否需要更新。
5. 在允许阶段修改安排；首批准后关键安排锁定。需要取消时明确确认，截止和最低人数按规则处理并通知相关人。

- 完成终点：饭局真实发布且招募结果可管理：成员/名额/截止一致，取消或未成团有明确终态；不是只交创建表单。
- 必要异常与退出：选店失败/DST歧义/无效输入/发布未知保稿；审核名额或版本冲突保留事实；确认取消前可返回，取消后不重开或自动搬人。
- 不做：平台支付/退款/库存、自动搬迁成员、以重新定最低人数绕过成团规则、代成员确认。
- 关联旅程：J01、J03、J04，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J03 赴约前沟通安排或调整参与

使用者：已获准的成员及该饭局发起人

触发：收到申请结果、需要查看见面安排、沟通或决定退出。

1. 从Inbox/Meals查看真实审批或取消进度，回到对应饭局。
2. 获准后打开有权群历史，查看安排、输入并主动发送消息；可让AI起草后转入原框再主动发送。
3. 查看新消息、在可见位置更新聊天已读；通知列表已读单独操作。
4. 决定不参加时退出席位；不想继续群聊时另行确认退群，发起人解散群聊也须独立确认。
5. 动作完成后看到准确参与/群状态及可读历史，重新申请获准也不补读离群空档。

- 完成终点：用户能完成一次实际协调或明确退出，并知道下一步去哪里；退席、退群、解散和饭局取消不会混成一个动作。
- 必要异常与退出：断网发送保稿、失败可重试；失权/退出停止旧发送；从未获准者不可读，退群/解散仅读授权历史，旧响应不污染新账号。
- 不做：提及/免打扰/系统推送增量、在线presence、AI私聊代发、替用户退出整场。
- 关联旅程：J01、J02、J04、J08，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J04 饭后记录体验并决定是否继续联系

使用者：有开始资格的同桌者、可补缺的发起人及互选双方

触发：一场饭局计划结束，想记录体验或联系同桌。

1. 在饭后入口确认/修改本人出席，发起人仅为尚未自报的人补缺，未知不作缺席。
2. 合格用户可分别给本顿饭私评分、写对他人的公开文字评价，选择是否私密再约。
3. 看清各项保存结果和发布时机，不把一个分项成功当全部完成。
4. 双方有有效共同出席且都愿意再约时进入私聊并主动交流，单方意愿不公开。
5. 任一方可撤回或拉黑；历史与未来写权限分开，解除不复活旧同意。

- 完成终点：饭后反馈各归其位；用户能在双方愿意时真正联系，或明确终止联系，而不是只停在互选成功提示。
- 必要异常与退出：7天窗口、资格未知/失效、分项失败/未知均说明原因并保稿；第三方看不到私评分/单方意愿；纠错和其他有效共同场次按规则重算。
- 不做：公开星级排名、人格推断、产品问卷混入单场评分、自动复活联系和常规争议审核队列。
- 关联旅程：J02、J03、J09、J10、J12，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J05 更新个人介绍或隐私选择

使用者：希望维护自己资料的账号本人

触发：从自己的资料/设置进入，想更新公开介绍或调整既有隐私/可选统计选择。

1. 查看当前公开资料及明确可修改项，知道哪些内容会公开。
2. 编辑姓名、介绍、语言等既有字段，或调整既有隐私/统计选择。
3. 保存并查看权威结果，再返回原页面；不愿修改时取消保持原值。
4. 需要退出账号时明确退出，回到访客入口，旧账号内容不继续回填。

- 完成终点：本人看到自己确认的最新资料/选择及保存结果；他人公开主页只看到允许公开的部分。
- 必要异常与退出：格式/长度就地说明；失败保留输入，跨设备版本冲突核对新值后本人确认，退出/切账号丢弃旧异步结果。
- 不做：账号删除执行、问卷内容、AI隐藏画像、新头像上传及新权限管理平台。
- 关联旅程：J01、J02、J06、J08，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J06 提交或更新一份产品意见

使用者：任何已登录、愿意自愿反馈的人

触发：从设置进入Product survey，表达对Fancy整体的意见。

1. 理解这份可选问卷不针对某顿饭，不要求先参加聚餐。
2. 选择是否愿再参加及可选原因，允许不答某项/清除原选项。
3. 主动保存，看到最新答案；返回后可继续查看或更新。

- 完成终点：本人可自愿提交并找回最新有效答案，未答不作No，未出席也不被挡住。
- 必要异常与退出：至少答一项；失败保留输入，不受饭后7天窗口限制，也不归因到某顿饭。
- 不做：增加新问卷、把产品原因切分单场评分、自动代答或统计分析页面。
- 关联旅程：J05、J12，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J07 举报问题并跟踪处理

使用者：遇到不当内容或安全问题的用户

触发：在正在查看的对象或会话中主动举报。

1. 明确举报对象和私密说明，知道举报不会公开给同桌。
2. 主动提交并得到最小回执，知道目前只是受理。
3. 返回本人事项查看受理/处理中/已回复，阅读实际回复或后续指引。

- 完成终点：用户完成求助且能追踪，不把收件成功或一张回执当作问题已经处理。
- 必要异常与退出：提交失败保稿/未知先查原次结果；仅本人能读回执；紧急问题不伪称平台应急服务。
- 不做：用户代支持人员作纠错、公开举报正文、开放全表数据或新客服平台。
- 关联旅程：J09，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J08 删除账号并确认处理结果

使用者：希望离开Fancy的账号本人

触发：从设置主动选择删除账号。

1. 读清对资料、未开始饭局/参与和联系的影响，可取消。
2. 重新认证并明确提交；受理前同步撤销会话/联系/群区间，处理未开始场次/申请并隐藏公开内容、撤销快照和旧导出。
3. 从最小回执看到处理中及实际完成情况，等待必要供应商撤销和物理清理。
4. 丢响应或回执不可用时查询原结果或未登录联系公开支持，不要求重新注册或恢复业务权限。

- 完成终点：账号删除从发起、受理、执行到结果恢复形成完整闭环，原会话/数据/导出不可继续使用；不只交一个删除按钮。
- 必要异常与退出：同步屏障全部成功才202，失败回滚；不影响已开始饭局他人资格；部分完成不冒称最终完成，公开参考号不是访问凭证。
- 不做：取消/退席/公开隐藏/快照撤销延后处理、清库、无限期保留或未经批准真实删除。
- 关联旅程：J03、J04、J09、J11，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J09 支持人员处理一宗举报或出席纠错

使用者：按个案获授权的业务支持人员

触发：从受理事项选择一宗有权限处理的案件。

1. 核对支持身份、个案权限、原举报和最小必要事实。
2. 按事项处理或回复；若出席自助窗口已结束，按原因/版本追加纠错，不改写原报告。
3. 检查资格、公评、联系和新统计的影响，旧普通快照保留原事实。
4. 记录原因/操作者/时间，更新用户可见处理结果并保留审计。

- 完成终点：一宗事项有可核实处理结论与正确传播，而非只有CLI退出0或已读消息。
- 必要异常与退出：逐步重新鉴权，结束满7天的精确边界、并发版本冲突和执行失败可恢复；不读取无关私密材料。
- 不做：完整客服后台、常规全量冲突核实队列、全表或聊天正文开放、直接SQL改历史。
- 关联旅程：J07、J08、J04、J11，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J10 查看约饭转化和供需并追溯原因

使用者：内部产品分析者

触发：想知道用户在哪一步未约成、供给不足还是出席证据缺失。

1. 进入有权后台，选择日期/分群及适用筛选，使用有效统计快照。
2. 从概览查看结果，再沿同一问题进入用户旅程或饭局供需。
3. 打开指标口径/来源和必要的伪名记录，分辨0、unknown、缺失和观察期。
4. 逐层返回原查询和位置，得到有证据范围的业务判断。

- 完成终点：内部用户能回答一个转化/供需问题并找到依据，不是逐页看到一些图表就算完成。
- 必要异常与退出：401/403/410/429/503恢复保留可保留查询，失效统计清除；中英及后台四档宽度可用，不泄业务原文。
- 不做：直接改出席、分类写入、导出全量个人信息、新因果模型或商家财务页面。
- 关联旅程：J01、J02、J04、J11，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J11 调整统计分类并拿到可信导出

使用者：有权数据管理员及读取结果的分析者

触发：发现测试/员工账号应排除，想重新看同口径结果或导出。

1. 在有权对象上核对当前分类、输入原因并主动保存。
2. 区分原次结果未知、分类已接受和统计待更新，不重复保存来催结果。
3. 统计失败时只重试统计，Ready后使用覆盖接受修订的有效快照。
4. 查看或导出同一快照/筛选聚合；若快照、角色或隐私已撤销，旧页面和旧下载都不可读。

- 完成终点：从分类修改到新结果/导出闭合，既不显示旧统计为新结果，也不只交付保存按钮。
- 必要异常与退出：丢响应查原意图，409本人重新确认；Pending/Failed禁旧结果，410清旧票据，删除后旧导出继续拒读。
- 不做：重复classify重试统计、不同用户revision混用、直接编辑业务事实和原始个人全量导出。
- 关联旅程：J10、J08、J09，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J12 分析饭后体验与后续赴约

使用者：内部产品分析者

触发：想分辨体验反馈、问卷意愿与实际再次参加的差异。

1. 选定有效快照和日期/人群，进入体验与留存问题。
2. 分别查看单场评分/反馈、独立产品问卷和成熟队列。
3. 下钻来源与后续机会/再次赴约，保留观察中与未知的解释。
4. 返回同一分析或按有权口径导出，不把意愿当实际复购/赴约。

- 完成终点：得到有观察窗口和分母依据的体验/回访判断，能追溯到权威事实。
- 必要异常与退出：问卷取asOf最新答案及该版本提交日期，未成熟不作流失；纠错/删除影响新结果不覆盖旧快照。
- 不做：预测/自动因果结论、新问卷、把饭局筛选套到产品问卷或统计造零。
- 关联旅程：J04、J06、J09、J11，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J13 邀请朋友查看并申请饭局

使用者：分享者及收到邀请的朋友

触发：在公开饭局详情选择邀请。

1. 选择系统分享、WhatsApp、微信复制或复制链接，得到公开事实内容。
2. 本人在目标渠道主动发送，取消不丢详情。
3. 接收方打开同一饭局，看最新状态；未安装App的落地方式先明确，不伪造可用网页。
4. 愿意参加的人按J01完成必要身份/资料并主动申请，仍等审核。

- 完成终点：朋友能实际接到邀请、理解饭局并进入正常申请，而不是只弹出分享面板。
- 必要异常与退出：复制失败有手动出口，满员/截止/删除文案正确；Q-SHARE-01未决则完整邀请不通过。
- 不做：默认开发移动Web、免审核/占位、联系人采集、自动外发或奖励。
- 关联旅程：J01，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J14 提及成员并让对方看到提醒

使用者：有权群成员、发起人和接收者

触发：在群里需要某人注意一条安排消息。

1. 选定当前同名成员或host允许的Everyone，形成明确提及而非纯文本猜测。
2. 编辑并主动发送，服务校验合法接收人并去重。
3. 接收方在站内记录/应用内横幅或主动授权的iOS系统通知中看到提醒。
4. 点击后定位有权消息；已可见、已读、退群/失权、过期和系统限制按规则处理。

- 完成终点：从提及选择到接收方实际有权看到消息闭合，不把事件入队或供应商接受当已送达。
- 必要异常与退出：失效成员降级、发送者失权保稿；纯文本不伪提及，退群重入不复活旧事件；拒绝系统权限仍有站内路径。
- 不做：presence、全端零重复、强制系统弹出、Web Push、群消息邮件和代外发。
- 关联旅程：J03、J15，各自保持同一业务事实，不让用户为内部模块切分重复操作。

## J15 减少群消息打扰但保留重要提及

使用者：希望调整本群提醒的本人

触发：从当前有权群设置选择免打扰。

1. 理解免打扰不会退群/隐藏消息，提及仍会提醒。
2. 主动保存本人+群设置，看到保存中/成功或冲突后权威值。
3. 回到实际使用场景，普通消息不弹但保留未读，重要提及仍按授权和平台能力提醒。
4. 在另一iOS会话读到同一确认设置，失权或退群后不能继续改设置。

- 完成终点：设置改变实际提醒行为并能恢复，不是只有一个开关看起来改变。
- 必要异常与退出：普通失败恢复最近确认值，409重新核对，不用旧表单覆盖另一设备；失败不报已保存。
- 不做：影响其他人、隐藏群内容、取消业务通知、越权恢复成员或新增通知渠道。
- 关联旅程：J03、J14，各自保持同一业务事实，不让用户为内部模块切分重复操作。
