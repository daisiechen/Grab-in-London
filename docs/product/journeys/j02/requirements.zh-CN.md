# J02 发起饭局并完成招募管理

版本：PM-r01｜交付集合：IOS-0.1.0｜需求输入：r07 / e7f2b89｜作者：PM-2｜状态：PM候选，待用户审阅；未启动UX、RD、QA。

## 1. 使用者、目标与本包范围

使用者是愿意组织一顿饭的成年人发起人。成功结果是完整发布一场可申请饭局，收到并处理申请，查看正确成员/名额/外订声明，必要时明确取消或看到截止终态；不是创建表单完成即交付。注册登录/资料门槛嵌在原创建意图内，新老用户分支复用J01身份规则，不要求先去独立账号模块。本包允许以合成申请人模拟J01的供给，真实跨旅程联合验证仍待后续。

做：四步创建、Google Places候选选店语义、伦敦时间/DST、最低人数/容量/截止、介绍/费用说明、本人外订声明、Review发布、查看申请者公开资料和批准/拒绝、声明更新、首批准锁定、截止/最低人数处理及整场取消；AI只生成创建草稿并显式转入。

不做：平台订位/库存/支付/退款、自动代审批/订位/发布、自动把旧成员搬到新场、移动Web、分享邀请、群提及或群push、客服后台。群聊和饭后页作为J03/J04业务交接，不在本包重新展开。

## 2. 完整路径与身份分支（J02-R01）

Create meal → 未登录则邮箱验证码或Google/Apple → 新用户填写姓名、简介、语言、生活状态、兴趣及18+/社区确认 → 回原创建草稿 → Arrange → Introduce → Costs → Review → 主动发布 → Hosting详情 → 处理申请 → 核对名额/锁定/外订声明 → 继续招募或取消/截止。

账号字段沿原合同：姓名trim后2–40、简介20–1000；邮箱验证码错误/过期/重发/OAuth取消失败和原意图恢复依J01共同规则，不能因Demo合成身份分支而删生产要求。已有合格资料不重复填。身份失效保留允许保留的草稿，退出/换账号清私人缓存；旧异步结果不能填到新账号。Demo邮箱校验和123456验证、合成OAuth、必填资料均可操作；真实OTP过期/发送/供应商链接/退出轮换为本包需求记录、J01合同联验。

## 3. Arrange：地点、时间、人数、截止（J02-R02/R03）

| 字段或动作 | 规则 | 结果与恢复 |
| --- | --- | --- |
| 餐厅搜索 | 名称、地址、地图区域走Places候选；支持范围内任意可识别餐厅，不是三家生产白名单 | 无结果/网络/配额失败保留原选择；可换词/区域重试，无手动新增兜底 |
| 确认餐厅 | 明确Use this restaurant；绑定placeId及许可显示的名称/地址/坐标，分店按ID区分 | 搜索文字/预览不等于已选择；更换餐厅清时间、外订声明、最终核对，其余草稿保留 |
| 地图与照片 | 正式Google组件/许可署名/对应餐厅照片，缺图占位，资源失效刷新 | 不用其他店照片冒充；无有效provider显示则明确不可验证，不能伪造资料 |
| 日期/时段 | Europe/London，全天48个半小时计划时间，不等于库存 | 重复时刻显式BST/GMT；不存在时刻拒绝；开始与截止同一校验策略，不静默修正 |
| minimum/capacity | 整数2≤minimum≤capacity≤6含host，默认3–4 | 显示嘉宾数及总人数；改人数重验、清失效外订声明/Review；双人也是友情优先 |
| closesAt | 默认开始−60分钟，可提前，最迟开始−30分钟；发布时仍晚于now | now≥closesAt禁新申请和审批，Pending→Expired；时区输入保存UTC+本地+offset |

本Demo固定合成时钟2026-10-24 13:00 BST、候选三条只是离线样例；查询/选店不联Google、不声称营业或订位已验证。生产餐厅范围及地图/照片/署名验收仍完整保留。Demo可输入2026-10-25 01:30检查歧义选择，2027-03-28 01:30检查不存在时间；不是拿静态月份当生产可用日期。

## 4. Introduce与AI草稿（J02-R04/R10）

标题trim后5–80、介绍20–1000；氛围/语言按已批准字典。host可选菜系European/Japanese/Spanish/Chinese；饮食Vegetarian options/Vegan可多选，未填存null，默认Not provided。来自host声明而非Places推断，不构成过敏保证；具体筛选unknown不命中、Any不排除。Demo饮食控件以单项候选演示，生产多选及共享字典在覆盖清单标为文档约束。

AI入口沿Ask Fancy现有能力：用户主动请求才生成，所用数据仅明确输入与获准公开字段；无群/私聊/评分/问卷/举报读取。创建草稿可给标题/描述及已知安排候选；不能伪造placeId、默认选店、默认勾选外订/条款，不能自动发布。用户点击转入；已有原文先询问保留/替换，取消保持原文；转入后仍需编辑、Review、主动Publish。重试不重复追加；超时/额度/权限变化保稿并可全手动继续。

中英、硬条件/软偏好/CLEAR、最小上下文/第三方许可、30分钟会话TTL、旧响应隔离、真实模型/数据/成本人民币50元/月硬闸按FR-13与批准方案随消费路径联验。Demo只展示确定性介绍草稿、替换确认和不可用恢复，不宣称接模型或花费已批准；完整助手设置由J05承接，不另立AI项目。

## 5. Costs、Review与发布（J02-R05/R06）

首发唯一费用方式为到店各自付款。预算budgetMin/budgetMax为正数、最多两位小数、min≤max，GBP整数便士存储；不是订金/收费报价。发起人明确声明自己联系餐厅，涵盖餐厅、时间、总人数及更新时间；声明是host报告，不是平台核实预约。声明未勾选不能继续；改变依赖安排须重新确认。

Review完整展示地点/地址、伦敦日期时间、最低/容量、截止、预算、介绍、语言/氛围、声明来源和未提供菜系饮食；各组Edit返回保稿。cancellation terms单独可读，打开不自动同意，返回保留Review及现有勾选。核对/条款必须本人勾选，发布前全量复验。

Publish以唯一原意图幂等：成功只创建一个meal及host一席，进入Meals→Hosting父级的详情，不能后退回已完成草稿。失败保稿可重试；Status unknown先查原意图，同key重试不再创建；不得无结果就另建一场。本Demo有明确失败与未知→查询路径；生产事务/未知已写/网络抖动全组合仍待RD/QA验证。

## 6. 申请处理、锁定与订位声明（J02-R07）

查看申请者公开介绍、本场留言及申请状态；只有本场host可批准/拒绝，不能读取其余私密资料。Pending不占位，APPROVE锁内重验本人身份、申请Pending、now<closesAt、饭局Open及剩余容量；成功直接Confirmed并首次入群，无付款/二次审批。末位并发只一人成功，失败保留原事实；DECLINED不允许本场重申；本人撤回/退席与新轮申请沿J01/J03。

首位guest批准永久锁定餐厅、日期时间、预算费用、人数范围、截止及host声明菜系饮食等关键安排。无人获准前可编辑并全量复验；页面编辑期间若另一端已批准，409加载权威锁定事实、保留草稿，不提交旧改动。需要改关键安排则取消重建；原成员必须重新主动申请，不自动搬人。

人数变化后旧bookingDeclaration显示Needs update；host联系餐厅后按当前确认人数主动重新声明，保留版本/时间。外订失败/取消不等于meal取消，也不关闭群。Demo审批后可实际看到人数/锁定/声明变更，重复处理同申请拒绝，不重复增加人数。

## 7. 生命周期、取消与交接（J02-R08/R09）

截止按历史成员状态检查confirmedCount≥minimum；不足则取消，达标后至开始前再次跌破最低立即取消，不允许降低minimum规避。延迟任务按计划检查时点重建，不能因为worker迟到就跳过终态。开饭冻结host及开始前有效确认未提前退出者名单，恰在开始退出不合格；开饭后不因人数变化自动取消，计划结束startsAt+2h后进入J04，不改写过去事实。

发起人仅开饭前主动取消，确认弹层说明影响全部人：关闭Pending→Expired，通知host和当前Pending/Confirmed，保留原群；原因host/booking/other，系统不足为insufficient，历史无原因为unknown。取消后不重开、不承诺平台退款，host自行联系餐厅。取消前Keep meal返回原状态；重复请求幂等。开始后取消拒绝并给支持说明。

关键通知矩阵：批准/拒绝→申请人站内+邮件；截止过期→申请人站内+邮件；整场取消→host及当前Pending/Confirmed站内+邮件；新申请/撤回/退出→host站内；声明变更→当前成员站内。邮件不得含申请留言、聊天、私密再约/举报正文。渠道失败不改业务结果，未知投递按provider查询/稳定ID恢复，不能在UI说“用户已收到”。首发群/私聊消息只有授权站内未读，无群邮件/push。Demo只展示合成事件日志，不外发。
