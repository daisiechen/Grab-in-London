## 用户目标、入口与完成结果

使用者是遇到不当内容或安全问题的本人。入口为当前可见成员/饭局/会话对应举报动作，明确对象后私密提交，拿到本人可查询的回执，再跟踪受理、处理中及实际回复。终点是用户知道求助处于何种阶段、可找回并阅读处理结果，不把“收件成功”写成“问题已解决”。Demo以成员举报为代表完整路径，不开发支持人员界面。

## 正常与取消路径

1. 用户查看成员，点Report member；若未登录，在原意图完成身份流程后返回举报对象，不自动发出。完整身份实现归J01，本包Demo有已登录/退出的合成前置。
2. 表单显示对象类型及稳定标识，选择原因、填写本人愿意提供的私密说明。原因必选且按批准枚举，说明可空；不新增未批准的最短字数或收费。输入仅本对象/账号草稿，不自动附加完整聊天或私密材料。
3. 本人主动Send private report，发送中防重复；成功返回最小reportId/状态和“已收到，将核实”，清楚是受理回执而非调查完成。取消保留适用草稿回原对象，不创建报告。
4. 在Your reports找到本人事项，查看Received / In progress / Reply available。用户主动刷新不重复提交，不制造新个案；读取实际公开结论或下一步，内部调查材料不返回。
5. 从回执返回本人列表或原成员，仍能找到同次事项。成员/同桌看不到举报；通知不得带举报正文。

## 输入、数据与权限

报告保存reporterId、targetType/targetId、合法reason、details、服务器受理时间、状态、版本及追踪关联。身份仅从当前认证，用户输入的reporterId不可信。公开参考号仅定位线索，不是访问凭据；查询需本人当前授权，换账号后原账号草稿/响应不串入。列表、单条读取及幂等重放都重新鉴权，不因知道ID得知他人说明/状态。

报告正文仅本人适用视图和此个案获授权支持可读；不默认允许支持查完整聊天或所有用户数据。前端纯文本安全呈现，不能执行用户输入HTML。正式数据保留和支持政策按已批准范围，不发明时效承诺。

## 状态、失败与恢复

| 情况 | 行为与反馈 |
| --- | --- |
| 未登录/无权 | 提示身份入口并保原对象；不向别的账号暴露报告 |
| 未选原因 | 关联字段错误，说明草稿保留，无写入 |
| 确定提交失败 | 明确未发送，原因/正文保留，可人工重试原意图 |
| 超时/结果未知 | 先查同次请求/幂等结果，不再创建新报告；明确没有再次发送 |
| Received | 已受理，等待人工处理，不显示已调查或已解决 |
| In progress | 支持实际开始处理，仅展提交者可见进度 |
| Reply available | 有实际回复/指引可读；回复不包含其他人私密内容 |
| 失权/切账号 | 停旧读取、清旧账号页面及迟到响应，只列新账号本人记录 |

## 平台、验收与不做

iOS英文，Fancy品牌，触控/焦点/标签/状态文字可理解，关键操作不被键盘底栏遮挡。紧急危险指引使用当地紧急服务，不假冒平台应急响应。真实投递、支持收件/身份/处理能力需后续真实证据，不能因Demo可点当作完成。

不做公开举报内容、举报者代支持改出席、自动惩罚、通用客服平台或J09完整处理界面。review里的支持处理/回复是明确外部角色模拟，与用户产品按钮分开。
