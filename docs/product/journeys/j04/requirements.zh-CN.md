# J04 饭后记录体验并决定是否继续联系

版本：PM-r01｜交付集合：IOS-0.1.0｜需求输入：r07 / e7f2b89｜作者：PM-2｜状态：PM候选，待用户审阅；未启动UX、RD、QA。

## 1. 使用者、目标及完整旅程

使用者为开始时有资格的同桌者、可以为缺报成员补报的本场host，以及双方自愿继续联系的人。Meals→Past→本场饭后页 → 本人出席报告/host补缺 → 可选独立私评分 → 对具体同桌写公评和/或选再约 → 看清逐项保存结果 → 双方有效选择后真的进入私聊发送 → 需要时随时撤回/拉黑并看历史只读。成功不是“互选成功”一张卡；必须有实际模拟可发私信与撤销结果。

本包做出席及资格、单场私评分、公评、私密再约、组合保存、私聊、撤回/拉黑/解除及资格纠错传播。不做公开星级排名/信誉或人格推断、自动联系人推荐、替对方同意、AI私聊代发、常规争议核实队列。Settings产品问卷由J06独立交付，不挤入饭后页，不从再约某人推断是否还愿意参加Fancy。

## 2. 时钟、开始名单与出席来源（J04-R01/R02）

计划结束scheduledEndAt=startsAt+2小时，只是开放饭后入口的计划时刻，不强制聚餐终止。自助窗口为[end,end+7天)，起点可提交、七天精确终点不可；不拿当地日历午夜替代连续UTC时长。

开始名单为host及confirmedAt<startsAt且未提前退出的成员；leftAt=startsAt排除，开饭后退出不抹他人资格；整场取消不产生新出席/反馈资格。未结束/无名单显示不适用而非缺席。本人仅报告自己，host仅本场开始名单成员；host自己仍优先本人报告。记录每来源版本/操作者/时间/幂等键，不使用默认全员出席。

有效结果：窗口内本人最新present/absent优先；本人未报才取host，均未报为unknown。两来源不一致仍是唯一明确结果，不增加“冲突待核实”第四业务状态，不把unknown当absent。窗口结束后仅J09获授权支持按个案追加原因/操作者/时间/版本的纠错，优先于过期报告，原历史保留，用户不能覆盖支持裁定。

Demo初始Mia在开始名单但未报告，Alex已自报present；Mia可主动报告，切host可补报Mia，回Mia能自报覆盖host。Noah不在开始名单，不能提交出席/反馈。评审时钟与支持纠错为独立外部合成前置，不作为常规用户按钮或真实个案授权。

## 3. 三类饭后对象及输入（J04-R03/R04）

| 对象 | 输入/粒度/可见性 | 资格与结果 |
| --- | --- | --- |
| MealExperience | 本顿饭score=1–5整数，按userId+mealId版本化upsert | 本人名单内有效present且窗口内；可只给分，不要求again/reasons；仅本人及获准分析/支持职责可读，不向同桌/host公开 |
| PublicReference | 对具体同桌trim后1–500字符，公开文字而非星级 | 本人及对象同场有效present、不可自评、窗口内保存；双方提交或end+7天后发布，发布仍需资格有效 |
| ReconnectSelection | 对具体同桌的布尔选择，独立版本 | 双方有效共同出席，本人窗口内主动选择，单方意愿保密；双方有效选择才开放私聊 |

保存评分不写公评/再约，公评不自动同意再约。空公评可跳过，不生成空review；首次未改任何项提示No changes to save，不伪造“反馈已完成”。已存公评不能用空白覆盖或静默删除，保留输入并说明限制。产品问卷为J06独立用户对象、无mealId、无出席/七天门槛；旧单场again/reasons不迁为问卷答案。

## 4. Save feedback组合保存与部分结果（J04-R05）

沿PATCH-004 §5.3保留一个Save feedback，但不新增跨接口原子保存。以最近权威快照比较dirty，仅提交改变的分项。保存绑定账号+mealId+subjectId，版本分别属于公评/再约，不能混用。

1. 本人已OPEN连接且本次取消再约会撤销双方同意时，先确认Withdraw connection。用户取消确认则整次Save任何分项都不提交，公评草稿保留；禁止先写公评再问是否撤销。
2. 确认/校验后，串行先公评后再约；无公评改变则跳过。公评确定失败、409或结果未知都暂停后项，后项显示Not saved yet，不能标为已执行失败。
3. 已成功分项保留、不回滚。公评成功而再约失败明确逐项“Public reference saved / Reconnect choice couldn't be saved”；重试只处理失败项和其后待处理项，不重复写已成功项。
4. 断网/超时为Status unknown，先查原次权威结果或同幂等请求核清，不重新生成意图；同一成功不加重复review/reconnect。409保留本地原文/选择，加载权威新版本，由本人核对后再确认；不默默覆盖。
5. 切对象/离开/换账号后迟到结果不写新界面，未决请求返回原对象先查。每operation实际提交时重新验证资格/版本/窗口，不因第一项成功就假定后项仍有资格。

Demo故障控制可让第一项失败、已保存但响应未知、冲突，或第二项失败/未知；回执逐项实际更新，Retry unsaved items不重复写成功项。合成未知结果预置已写入的权威状态供查询，不代表真实断网服务已验。

## 5. 联系、私聊及撤回（J04-R06/R07）

互选按人对形成持续联系，至少有一个双方有效出席依据，双方当前epoch同意且无有效block。单方只显示本人保存结果，WAITING不能暗示对方是否选择；其他同桌/第三账号不能读单方选择或私信。本人不因看见互选卡就自动发送；进入实际私聊、输入1–2000纯文本、主动Send。每次发送重验身份、双方意愿/拉黑及有效共同依据；会话历史读取与未来发送分别授权。

任一方随时撤回清双方同意、epoch前进，历史私聊按曾有参与授权只读；重新联系需双方新选择，选起仍须有窗口内合格共同饭局。revokeConnection按人对授权/版本执行，不附加mealId、七天窗口或新的共同出席门槛。超过七天的OPEN连接：独立Withdraw及公评无改变的Save+取消再约均可撤回；若公评dirty且过期组合Save，先公评被拒、revoke显示Not saved yet，但独立Withdraw仍可随时执行。

拉黑清双方同意，禁止未来私信，不改变共享群成员关系；解除拉黑只移除有效block，不复活旧同意。安全问题另可J07举报/独立退群，不读取第三方材料。对象隔离：Mia↔Alex联系不能误关Mia↔Noah；第三账号不得通过ID读取私信。

## 6. 纠错、发布与统计传播（J04-R08）

出席被合法纠错为无效后，相关公评不再公开，私评分退出有效统计，单方选择不能继续产生授权；保留原始修订历史，资格恢复按原规则重新计算而不重复计数。若联系另有有效共同场次且双方授权仍在，则不因一场纠错误关整个人对。已明确撤回/拉黑清除的同意则不能被资格恢复复活。

旧普通snapshot保留原asOf，新快照体现修订；申请→出席结果从end+24h才成熟，不等于冻结，七天补报/支持纠错影响新统计。J09负责真实个案授权、J10/J11/J12负责正确新旧统计与导出，本包不新增分析或支持操作台。

## 7. 权限、失败与返回

- 未结束、名单外、cancelled、unknown或absent各给可理解原因；本人可报告时给入口，逾期给支持指引，不把资格问题叫网络失败。
- 私评分、公评、再约分别保存结果；禁用/失败仍保留可恢复输入，未选私评分不是0，没公评/再约不强制填。
- 拒绝/撤回/拉黑/纠错后发送停止，历史只读不被删除；未发送文字可复制/删除，不做离线自动发送队列。
- 出席/评价/选择版本冲突，清晰显示新权威事实并保留本地draft；账号/对象切换不串写，不在UI显示另一人未互选选择。
- 确认前返回不写；返回Past保留适用已存分项与未存草稿，不把进入页面算成“已完成反馈”。
