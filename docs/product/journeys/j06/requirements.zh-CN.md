# J06 提交或更新一份产品意见

候选PM-r01｜IOS-0.1.0｜输入r07／e7f2b895｜需求与Demo供用户审阅；UX/RD/QA未启动。

<a id="goal"></a>
## 1. 用户目标、对象与完整结果

任何已登录、愿意反馈的人，可从Settings→Product survey自愿表达对Fancy整体的意见，不要求先参加某顿饭。用户需要能提交、回来找回最新答案并更新，清楚知道未答、保存失败和已保存的区别。问卷是按账号的产品反馈，不是单场私评分、公开个人评价或私密再约。

完整路径：设置入口→理解问卷可选且面向产品→选择一项或多项→主动保存→看最新答案→返回设置→重新打开查看或更新。取消不提交，跳过不影响核心约饭。无mealId、无出席资格、无饭后7天门槛。

不增加新问卷、长自由文本、公开结果页、成员评分、后台分析页面或自动代答。J05提供设置归属，J12消费问卷分析，但后置J12不允许删除首发问卷生产能力。

<a id="survey"></a>
## 2. 字段与校验

| 字段 | 规则 |
| --- | --- |
| again | Yes / No / null三态，默认null；选择“不回答/清除”回null。未答不能记No，不默认预选Yes。 |
| reasons | 可多选company / conversation / coordination / expectations / venue / cost / other，允许空，重复值去重。界面用自然语言label，不要求全选或填原因。 |
| 保存条件 | again非null或至少一个reason即可保存；两者都空阻止保存并说明至少回答一项，保留输入。 |
| 主体 | 从已认证的本人账号确定userId，不信客户端任意主体；本人查看/更新，不能读别人的私密答案。 |
| 版本 | 按userId保存最新有效版本、submittedAt，更新同一份意见而非每次产生一个被重复计人的新问卷。保留必要修订，不携mealId。 |

清除again但保留reason仍可保存；只回答again且理由空也可保存。取消编辑恢复最近确认值；首次空白取消不写任何答案。问卷不根据出席、单场评分、再约或Profile偏好自动推断。

<a id="recovery"></a>
## 3. 状态与恢复

- 初始未答、编辑未保存、保存中、已保存、保存失败各有区别；处理中避免重复提交，不以按钮已按下当作服务端已保存。
- 保存失败保留选择并可重试，返回后重新读取最近权威成功版本；旧失败不能覆盖成功结果。账号失效/切换停止旧响应，清本机私密答案，不搬给新账号。
- 服务器未知结果先确认原次状态，再按既有幂等/版本合同恢复，不重复记人。离线/无权限明确反馈，不伪造“已收到”。
- 不限制饭后7天，未出席或过了任何一场饭的窗口仍可保存。删除账号后问卷按删除政策退出有效数据与统计，不维持可关联匿名副本。

<a id="privacy"></a>
## 4. 隐私与分析消费约束

答案不向同桌/host公开，仅本人及按职责获准的分析/支持消费。问卷不归因到饭局：不能从“不愿再见某人”推断不愿参加Fancy，也不能用产品原因切分某顿饭的单场评分。

后台在asOf先取每人最新有效版本，再按该版本submittedAt纳入日期，不回捞日期区间旧版；日期与用户分群生效，区域/预算/语言/来源等饭局筛选不套在产品问卷。分析端J12另交付，本包只保留消费合同与可证明的源字段，不建统计页。

<a id="demo"></a>
## 5. Demo和验收条件

自然页面为Settings→Product survey→Saved→Settings→View/Update。评审区可选择有无出席、模拟超过7天及下一次保存失败，正常页面不出现这些工具。数据仅本页内存，无网络和持久化；真实保存/身份安全未实现，不能以这个模拟关闭原QA门槛。

- J06-AC01：未出席的已登录本人可进入并自愿作答，默认again=null，跳过不影响约饭。
- J06-AC02：三态、七原因、多选/去重、至少一项、清除again及取消不误保存准确。
- J06-AC03：主动保存→查看最新→返回找回→更新为同一人的新版本可连贯完成。
- J06-AC04：保存失败保选择，重新成功不重复计人；跨账号/无权/删除遵循私密合同。
- J06-AC05：无mealId、出席或7天门槛；单场评分与问卷的输入/权限/统计日期分开。
