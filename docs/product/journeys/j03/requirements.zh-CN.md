# J03 赴约前沟通安排或调整参与

版本：PM-r01｜交付集合：IOS-0.1.0｜需求输入：r07 / e7f2b89｜作者：PM-2｜状态：PM候选，未启动UX、RD、QA。

## 1. 谁要完成什么

使用者为收到申请进度的人、已获准成员、发起人和有授权历史的离群者。一次完整旅程：从Inbox/Meals找到准确进度 → 进入本人有权的群 → 实际收发一次安排消息或明确调整参与 → 看见可继续做什么。不能停在一个聊天列表或退群弹层。

本包做Inbox/Meals状态、基础业务通知与通知已读、群授权历史/消息收发/实际可见已读、AI群稿显式转入、开饭前退席、独立退群及host解散、重入区间与恢复。个人私聊业务资格及完整私聊路径由J04交付，共用消息合同不另创一套。后续J14/J15的@、横幅/系统群push、mute不在首发；普通群消息不新增逐条通知列表或邮件。

## 2. 入口、角色与完成路径（J03-R01）

| 角色/状态 | 可见与可做 | 不可做 |
| --- | --- | --- |
| 待审/拒绝/撤回/过期且从未入群 | Inbox本人申请进度、对应公开饭局 | 读取群历史、实时成员名册或发送 |
| 首次获准 | 直接Confirmed并入群，读授权历史、主动发送 | 再加二次批准/付款门槛 |
| 已退席但未退群 | 显示座位Cancelled及仍在群，继续聊天 | 将退席假写成已退群或仍Confirmed |
| 独立退群 | 授权历史只读、保留未发文字可复制/删除、设置只读 | 新发送/新轮询/实时名单或空档消息 |
| host | 同上当前群权利；可明确确认解散 | 以解散改变席位、出席或重开已解散群 |
| 从未参与的其他账号 | 对象不可访问，不能枚举私密信息 | 猜ID读申请/聊天 |

Inbox可呈现Pending/Confirmed/Cancelled等准确来源、日期/host/对应mealId；Meals沿原Upcoming、Applications、Hosting、Past、Cancelled，分类与申请轮次不混。成功打开Meal/Chat及返回保持正确上下文；未登录走J01完整身份/资料回流，不自动申请/发送。此Demo初始为Mia已登录且获准的合成场景，评审可切Sam待审或Alex主持人；不能把角色选择当真实认证/权限证据。

## 3. 消息、历史授权与已读（J03-R02/R03）

授权历史是历次membership intervals的并集：joinSeq < message.seq < leaveSeq，open interval无上界；读取/发送每次由服务端检查。退席、饭局结束/取消、外订失败均不自动关闭群，只有明确退群/解散/账号权限撤销按规则撤写。退群后历史API继续可读，不能笼统403抹掉历史；重入新增区间，不补读离群空档，也不泄露隐藏正文/发送者/数量。

用户输入纯文本trim后1–2000，标签/HTML不执行。clientMessageId标识同一次发送；重试同ID不重复消息或通知，不同body冲突不覆盖。成功反馈说明该消息已在权威会话中受理/可见，不冒称对端已读。断网/429/503保留草稿，明确失败及用户重试；不做离线自动发送队列。401清本账号私密cache并走登录；403停止未来发送/实时轮询，回本人授权历史或明确不可访问；账号变化、退出或权限撤回后，旧响应丢弃，不插入新账号或另一群。

只有本机实际渲染并在可见位置的消息才能推进聊天readSeq。打开聊天不等于所有未加载消息已读；滚动旧消息时保留新消息提示，不强制滚到底。通知列表的已读是另一对象，需本人显式标记，读到聊天不能自动清通知；反之标通知已读不清群未读。Demo整个短消息列表可见时推进已呈现位置，评审切换旧消息可检查未读保留；生产IntersectionObserver/分页/前后台/多设备读位按原契约再验。

## 4. 座位、退群与解散（J03-R04/R05/R06）

退席：仅guest在now<startsAt且当前Confirmed时操作，确认说明释放本人席位，不退出群；结果为本人参与Cancelled并释放一席，向host发送对应站内事件。截止后跌破最低可导致整场取消，由J02权威生命周期负责。开始后不能退席抹除资格，改由饭后报告或支持。host不能使用guest退席代替整场取消。

退群：当前写成员主动选择、确认后关闭本人区间，不改变meal participation或开始资格；可取消确认而无状态变更。成功留在Group settings，显示Left group及只读说明；隐藏整个当前成员名单、人数、搜索和@候选，接口同样不能返回实时名册。保留返回本人既有历史入口，不新增离群时成员快照。

解散：仅具有当前群写权限的host，确认影响全员，关闭所有open intervals，未来所有成员只读；不改变任何席位、不自动取消饭局。解散是终态，不因重申获准而重开。guest伪造解散服务端拒绝。

重入：不是一个“恢复消息权限”开关。本人先前退席、在可再申请条件下生成新轮申请，Pending仍无新群权；host真实批准且群未解散后才能新增授权区间。若本人只退群但仍有有效席位，不制造重复申请。原有区间继续只读，空档永远不补。Demo通过明确合成host批准检查该边界，不代表真实跨用户联调。

## 5. AI群消息草稿（J03-R07）

用户明确mealId且有当前群写权限，才能生成协调文案。仅公开饭局时间地点和本人明确输入，不读取群/私聊正文、未发他页草稿、单方再约、评分/问卷、举报或后台。Demo确定性草稿不冒充真实AI。

生成 → 可读草稿卡 → 用户点击Use this draft → 若已有输入先保留/替换确认 → 原消息框可编辑 → 用户主动Send。生成、转入、重复点击均不发送；转入和实际Send再次鉴权。退群/解散/失权后旧草稿不能借入口恢复权限。取消替换保留原文，AI失败/额度用尽仍可自己输入。

草稿建议≤1000，但最终消息按核心1–2000合同；不虚构其他人出席或引用未读群内容。中英文、FR-13会话30分钟TTL/1在途/迟到响应丢弃、第三方许可/最小数据、真实模型质量/预算硬闸均是消费合同，不因本Demo不联网而移出首发；偏好管理由J05，账号删除清理由J08。

## 6. 业务通知与跨旅程事实（J03-R08）

站内通知是权威，关键审批/取消另发邮件：获准/拒绝及截止过期给申请人；整场取消给host及当前Pending/Confirmed，不给已撤回/退出者继续发邮件；新申请/撤回/退出给host站内；外订声明变化给当前成员站内。群/私聊消息只产生授权未读，不新增群邮件或首发系统push。

业务事件、站内通知、邮件队列各按稳定事件+接收者+渠道去重，受理与实际送达分开；未知邮件结果先查提供方/稳定ID，再按原有限重试恢复，不能显示“已读/已收到”。消息/通知payload不包含申请留言、私密反馈、举报正文。退群不必取消仍适用的业务通知，也不能扩大聊天历史读取权限。

## 7. 必要异常、取消与返回

- 点击已有申请进入对应轮次，状态过期/取消使用最新事实；Pending不造会话权限。
- 消息空白/超长就地错误且保稿；失败明确Not sent，恢复在线后本人再发；失权停止旧重试。
- 退席/退群/解散均先说明不同后果，取消确认无写入。失败保留最近权威状态，409加载新值而非重放旧决定。
- 切换群、账号、离开页面后，按对象+账号绑定的旧消息/通知/AI响应不得串写，Logout清账号本地草稿/会话cache。
- 回群历史无权明确解释，不泄当前人数/名册/空档元信息；取消/结束后仍有权群不能误设只读。

## 10. 共用约束、现状与后续专业交接

iOS英文、London时间、Fancy既定品牌/触控焦点/语义错误、键盘不遮输入、长内容滚动；正常界面无工程控制。服务端检查身份/当前授权/版本/幂等，公开DTO不含邮箱/联系人/私密选择；消息正文不进入分析/日志，采集只记录获准业务事件及成功结果。
