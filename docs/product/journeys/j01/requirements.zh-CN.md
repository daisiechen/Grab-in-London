# J01 找到并申请一场合适的饭局

候选：PM-r01｜交付版本：IOS-0.1.0｜输入：r07／e7f2b895｜状态：供用户同时审阅PRD与Demo，不代表产品批准或实现验收。

<a id="goal"></a>
## 1. 用户目标与完整终点

Fancy让伦敦18岁以上成年人通过吃饭认识新朋友。想参加的人可以先浏览、找合适的时间地点和预算，再主动向发起人表达申请。首次使用者在申请途中完成完整注册/登录与必要资料，返回同一饭局后自行提交；老用户不重复填资料。完成点是唯一申请被受理并可查看待审、撤回和再次申请资格，不是验证码成功或资料表单完成。

本旅程不做发布/审批/支付/群聊/私聊；需要后续J02审核，批准前Pending不占席位也不授群读权。真实AI是首期需求，用户可以完全手动操作，不能以一个规则模拟助手替代真实AI最终验收。

<a id="discovery"></a>
## 2. 浏览、筛选、详情和公开资料

自然入口为欢迎/Discover地图或列表，也可以从同一mealId详情进入。游客可看公开饭局、公开主页和已发布公评；邮箱、申请留言、私密偏好/反馈、完整行程与消息不进入公开投影。

- 默认地图；区域标记表示匹配饭局数量，卡片人数表示含host的总人数与已确认/剩余。切地图/列表保留筛选和选中饭局，区域列表/分页由同一结果集产生。
- 日期可选多个未来日，日期内部OR，与区域/预算/人数/语言/时段/氛围/菜系/饮食/关键词等条件AND。打开复制为草稿；Apply生效，Clear只清草稿，关闭/取消不应用。0结果可应用并清筛选，服务失败不能冒充0结果。未来日期无饭局也可选择，过去日期不可选；月份导航及键盘日期选择沿用原FR-01a。
- 人数含host，不是替多人申请；一次申请仅代表本人。预算以预计区间上限比较，未知预算不称预算内，GBP。Cuisine/饮食由host可选声明，unknown不命中特定硬条件但Any不排除；不由店名或Places推断，不保证过敏安全。
- 正式字典沿用已批准code：EUROPEAN/JAPANESE/SPANISH/CHINESE；VEGETARIAN_OPTIONS/VEGAN；EASY_CONVERSATION/FOOD_DISCOVERIES/TRAVEL_CULTURE；语言为BCP47（en/zh/es/fr等既有映射）。界面显示友好label，不新增可提交枚举。
- 详情说明餐厅/区域、当地时刻、预算/人数、host、语言/氛围、介绍、host-reported约定及外订声明；不是餐厅库存或平台已订。用户到店各付，首期无订金。公开头像入口与整卡入口不冲突，返回恢复原位置。
- 申请动作按本人角色/当前状态显示：host不能申请自己、Pending不重复、被拒本场不重申、满员/截止/取消/开始不新申请；明确原因。餐厅真实placeId/地址/地图外链/照片署名许可仍有真实Places门槛；Demo餐厅名称与几何地图全为合成，不冒称Google照片。

<a id="identity"></a>
## 3. 在原申请途中完成注册或登录

用户点击Apply后进入账号入口；未主动申请前不强迫注册、不请求定位/联系人/通知权限。邮箱格式去空白，6位验证码5分钟有效（等号过期），重发30秒冷却（等号允许），新轮次使旧码失效；错码、过期、请求/验证失败保留适用输入，可改邮箱/取消。不能用不同公开提示探测邮箱是否注册。

Google与Apple沿用等效入口，模拟中各有取消和返回；正式供应方鉴权、身份冲突/链接不得自动合并同邮箱，真实回调/PKCE/频控/一次消费与跨账号隔离必须独立验收。

新用户完整填写公开称呼2–40字符、简介trim后20–1000字符、生活状态、至少一种语言/兴趣，并确认18+和社区规则；选填职业/学校/家乡不强制。缺项阻止继续，保存失败保稿。资料已完整的老用户直接回原饭局申请。资料/认证取消返回原意图，不能伪称已经申请。原目标mealId和未发介绍在过程内保留；跨账号不搬私密稿。

<a id="application"></a>
## 4. 主动申请、待审、撤回与恢复

回同一mealId后读取最新名额/截止/资格，用户输入20–300字符介绍，明确确认安排后主动提交；已有人工稿不被AI无提示覆盖。业务服务按原规则鉴权、幂等与原子校验，同人同场最多一个有效申请/席位。Pending不占位，批准由J02完成且直接Confirmed，不走付款保留。

提交成功得到唯一applicationId并在本人Applications/详情可找回待审状态。未知结果先查询原请求，不另建一条；确认未接受才可按原意图重试。满员/截止/取消、资料或权限变化拒绝并保原稿，不能以旧卡片保证名额。网络失败、离开/返回、旧响应不清新稿。

本人Pending可确认撤回（可取消），成为WITHDRAWN；截止前且有名额可新一轮重新审核，旧历史保留。DECLINED本场不可重申；EXPIRED不重开。后续个人退席不在本旅程，待J03；host审批和原子最后名额在J02联合验证。返回发现保持筛选，不因申请或AI改写Discover状态。

<a id="ai"></a>
## 5. 可选AI辅助：查询、解释、草稿与人工提交

### 5.1 请求、条件与可核证结果

用户主动发送才触发处理，空白不发送，文字≤2000，中英按输入语言回复；无日期/当前筛选时从伦敦当天起未来7个日历日，日期/周五/下周五/今晚/周末/DST歧义按FR-13确定或追问，不能静默改日期。最多提供20个权限过滤的候选给模型，每轮最多3张结果/比较卡，不把全库交给模型自行搜。

明确本次修改＞本会话确认条件＞当前Discover已应用筛选组成hard；账号已确认偏好仅soft排序。明确不限预算/任何区域为CLEAR，下一轮不能被旧soft恢复，不自动改Discover。预算£35偏好仍可出现£45但排序在后；用户本次明确£35才排除。unknown饮食不命中特定hard。满足hard后偏好命中数、开始时间、稳定mealId可复现排序，不插推广。需要更便宜先提出上限让本人确认，不擅自扩大区域或改日期。

只澄清本次阻碍；如Spanish无法分菜系/交流语言先问，未明确饭局不生成针对某场的申请。排除满员/截止/开始/取消、本人主持和不可重申场；本人Pending/Confirmed仅在明确询问时解释，不称可新加入。卡片事实有来源版本/取数时间，详情、转入、提交逐次重验；无匹配、数据服务失败与模型失败分别表达，不编造状态。

### 5.2 数据、许可与权限

首次真实使用前明确供应方、处理地域/训练/留存、必要上下文并取得适用明确许可；拒绝仍可手动查找和申请。模型只读本人主动输入、当前获准公开饭局、明确请求解释的本人状态及经本人同意的最少公开介绍；不读群私聊正文、单方再约、未发布公评、私评分/问卷、举报、支持或后台，不从外部文字获得新权限。未知URL/ID/字段、提示注入、虚构人物/经历和越权请求拒绝，不把整个Me/Meal响应上传。

### 5.3 申请草稿

明确mealId→生成候选→本人点击转入→原编辑器校验→本人Send。生成/重试/转入均不创建申请或席位。AI候选上限≤500字符，但原申请字段20–300的最终限制仍生效：超目标长度提示缩短，不静默截断。生成不自动勾安排/条款，不编造学校/职业/关系。目标已有稿时明确Keep/Replace，取消保留人工文字；重复转入不追加；编辑器实例、账号、饭局、资格变化后丢弃旧响应。

### 5.4 会话与成本

同会话最多1在途，请求30秒硬终结，超过3秒仍表明处理中；无循环自动重试或部分输出可提交草稿。设备对话不跨端同步，登录偏好共享，游客偏好不自动迁入账号。打开不自动调用；关闭保留尚有效对话，显式Continue才恢复；New conversation清本设备会话/临时条件，不清原业务编辑器，30分钟闲置保留未发文字及明确偏好，丢弃旧候选和迟到响应。

DeepSeek与人民币50元/月全局硬闸按批准合同执行，请求前预留、UNKNOWN保留责任，价格/数据/金额无有效批准时关闭真实调用；不是充值或新费用授权。建议日轮次/频率及质量/延迟数字仍按参数审阅与最终合同处置，不能把建议默认为已批准。需要真实60样本/四项零容忍/质量延迟/usage账单等原门槛；规则模拟和作者测试不能关闭。模型停用/配额耗尽不关闭普通查找申请、偏好删除，不额外收费。

## 6. Demo覆盖与必要恢复

从Discover开始，地图/列表、筛选Apply/Cancel、详情/host、账号三方式、完整新用户资料、申请/待审/撤回/重申可连贯操作。画面外评审控制选择老用户、满员、截止、认证/保存/提交/未知响应/AI故障及合成时钟；手机内不显示工程状态。邮箱仅接受@example.test是演示限制，不是正式产品限制。OTP码显示在评审区；模拟OAuth不假冒真实供应方权限页。

AI使用确定性合成语句和数据：可试“周五Soho、£35、4人”“any budget”“Spanish”，选择结果、Compare、Explain、Draft、Keep/Replace与主动Send。实际语义解析、任意日期/语言、模型事实/注入验证及真实质量/费用是文档约束与后续真实门槛，不由演示冒称实现。公开地图/餐厅/照片、持久化/多人并发/原生手势和邮件未接入。

<a id="acceptance"></a>
## 7. 用户验收与文档效力

- J01-AC01：访客先浏览/筛选/详情且返回保上下文，公开投影无私密字段。
- J01-AC02：邮箱及Google/Apple取消失败可恢复，验证码冷却/过期不绕过，老用户无需重复资料。
- J01-AC03：首次用户填完必要公开资料与确认，返回同一mealId，仍由本人主动申请。
- J01-AC04：有效提交产生唯一Pending，查询未知结果不重复，撤回/重申轮次准确，不占席位/不授群权限。
- J01-AC05：满员/截止/失败/版本与会话变化保留适用输入，不能静默提交或清新稿。
- J01-AC06：AI硬条件/soft/CLEAR、澄清/结果比较/解释及失败退回手动正确；查找/草稿/转入不是业务成功。
- J01-AC07：转入Keep/Replace、目标/长度/权限再验且手动Send；原隐私/生命周期/费用和真实评测要求完整保留。
