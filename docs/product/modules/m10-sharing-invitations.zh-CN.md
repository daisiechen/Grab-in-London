# M10 分享饭局与邀请落地需求说明

需求修订：r04｜状态：产品需求草稿。

## 为什么需要、谁使用

用户想把公开饭局介绍给朋友；朋友应能先查看、再自行申请，无须预先安装App或被自动加入。

使用者：希望邀请朋友的公开饭局浏览者，以及收到链接的朋友。

本版适用端：iOS App。 产品背景、功能范围与产品角色见[整体MVP需求](../fancy-requirements-baseline.zh-CN.md)。

## 用户从哪里进入、怎样完成

入口：饭局详情Share meal菜单，接收方打开稳定HTTPS饭局链接。

1. 用户主动打开分享菜单，选择系统分享、WhatsApp、微信复制、复制链接或邀请文本。
2. 分享内容仅含公开标题、当地时间、餐厅/区域和稳定mealId链接。
3. 用户在外部目标主动选择联系人并发送；取消返回原详情且保留状态。
4. 已安装App的接收方在iOS中打开同一饭局，看到最新状态与不可申请原因；未安装App者的落地方式待确定，不承诺移动Web可用。
5. 接收方需要参加时完成登录/资料后返回同一场次，自行提交，仍等主持审核。

## 必须保持的业务规则

- 分享不占位、不免审批、不包含token/申请留言/消息/邮箱/私密资料。
- 满员、截止、取消或开始/结束仍可分享事实详情，文案用View meal而非Join；删除/无权对象不可见。
- 微信使用复制文本/链接，不承诺专用SDK、定制卡片或朋友圈直发；系统面板目标取决设备。
- 复制成功回执只在真实成功后显示；系统回调不证明朋友已收到或已加入。

## 失败、返回与取消

- 系统分享取消不显示发送失败；不支持/剪贴板失败保留可选中文本和手动复制路径。
- 链接不能借外域重定向或私密query绕权限；失效链接显示不可用。
- iOS App未安装时，不显示虚假的网页兜底或自动加入承诺；接收路径尚未确定，完整邀请闭环仍待明确。

## 版本范围与可观察验收

### D15 Web分享与接收（后续版本）

范围与终点：移动Web分享与接收，移至后续版本，本版不做。


- D15-AC01：后续移动Web版本让朋友通过公开链接查看同一饭局，登录后仍需主动申请。
- D15-AC02：后续移动Web系统分享取消不丢状态，复制成功真实，复制失败有手动选择文本的出口。
- D15-AC03：后续移动Web中的WhatsApp与微信复制按目标渠道正确打开，不能借分享绕过名额和权限。

### D16 iOS分享与公开链接

范围与终点：iOS系统分享与公开链接冷/热打开；未安装App的接收路径尚待确定，不含移动Web兜底。


- D16-AC01：iOS用户可主动打开系统分享或复制公开链接/邀请文字；取消返回详情，不显示朋友已经收到。
- D16-AC02：已安装App的接收者能打开同一饭局并看到最新状态，登录与申请仍沿用原规则。
- D16-AC03：未安装App者如何查看邀请尚待确定；本版不承诺移动Web兜底，这条产品问题解决前不称完整邀请闭环已完成。

## 相关功能与范围边界

详情见M02，登录见M01，申请见M04；分享只帮助朋友找到饭局，不授席位或群身份。
