# M10 分享饭局与邀请落地需求说明

需求包修订：r02｜文档性质：项目协调负责人的模块需求输入｜状态：待用户审阅，未签发实施工作包。

## 为什么需要、谁使用

用户想把公开饭局介绍给朋友；朋友应能先查看、再自行申请，无须预先安装App或被自动加入。

使用者及职责：浏览公开饭局的访客/用户、收到链接的人；外部App由用户选择并主动发送。

适用端：移动Web与iOS。背景、术语、规则权威及授权见[整体需求基线](../fancy-requirements-baseline.zh-CN.md)。本说明写用户结果，详细字段/接口由对应产品经理和研发人员按原规则展开；不以现有代码反推需求。

## 用户从哪里进入、怎样完成

入口：饭局详情Share meal菜单，接收方打开稳定HTTPS饭局链接。

1. 用户主动打开分享菜单，选择系统分享、WhatsApp、微信复制、复制链接或邀请文本。
2. 分享内容仅含公开标题、当地时间、餐厅/区域和稳定mealId链接。
3. 用户在外部目标主动选择联系人并发送；取消返回原详情且保留状态。
4. 接收方以移动Web或iOS打开同一饭局，看到最新状态与不可申请原因。
5. 接收方需要参加时完成登录/资料后返回同一场次，自行提交，仍等主持审核。

## 必须保持的业务规则

- 分享不占位、不免审批、不包含token/申请留言/消息/邮箱/私密资料。
- 满员、截止、取消或开始/结束仍可分享事实详情，文案用View meal而非Join；删除/无权对象不可见。
- 微信使用复制文本/链接，不承诺专用SDK、定制卡片或朋友圈直发；系统面板目标取决设备。
- 复制成功回执只在真实成功后显示；系统回调不证明朋友已收到或已加入。

## 失败、返回与取消

- 系统分享取消不显示发送失败；不支持/剪贴板失败保留可选中文本和手动复制路径。
- 链接不能借外域重定向或私密query绕权限；失效链接显示不可用。
- 未安装App可走Web；原生冷/热启动和关联域名须实测，不由单元解析测试替代。

## 版本范围与可观察验收

### D15 Web分享与接收

范围与终点：公开投影、复制/降级与另一设备的移动Web申请回流。

前置需求版：D02、D04。

- D15-AC01：公开链接另一设备访客可读正确mealId，无敏感字段，登录后仍须主动申请。
- D15-AC02：系统取消、复制内容及失败降级有真实浏览器证据，UI显示Copied不单独作内容证明。
- D15-AC03：WhatsApp预填与微信复制接收按真实目标渠道验；未安装/未打开标未测。

### D16 iOS分享与公开链接

范围与终点：新原生构建系统面板与公开链接冷/热启动，Web兜底。

前置需求版：D15。

- D16-AC01：系统分享取消保留原详情，设备复制/目标渠道内容正确。
- D16-AC02：配置域名下同一mealId冷/热打开正确，非法/不可见链接不泄露信息，未安装走Web。
- D16-AC03：记录设备/OS/构建与实际关联域名；缺AASA/签名/设备不以链接纯函数关闭。

## 依赖、职责与不做事项

模块交接：M02负责公开详情，M01/M04负责登录与申请；M10不改变名额或成员状态。

本模块不做：邀请奖励、通讯录、自动外发、目标追踪、渠道转化后台。

最小测试前置：受控HTTPS公开入口、两设备/浏览器、可用目标App；D16单独需要Mac签名构建/关联域名。

上述验收是需求条件，不是已经执行的结果。受控测试、实际浏览器/设备、真实服务及联合旅程分别记录；原要求中的真实门槛未齐必须保留阻塞。一次模块验收不代表发布批准。
