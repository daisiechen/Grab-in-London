# M08 产品数据与管理后台需求说明

需求包修订：r02｜文档性质：项目协调负责人的模块需求输入｜状态：待用户审阅，未签发实施工作包。

## 为什么需要、谁使用

内部团队需要知道用户能否找到饭局、为什么未约成、是否真实见面和是否再次参加，同时能辨认统计缺失及观察期。

使用者及职责：产品分析者读脱敏统计；数据管理员维护测试/员工分类；支持个案人员职责另在M07。

适用端：内部Web后台。背景、术语、规则权威及授权见[整体需求基线](../fancy-requirements-baseline.zh-CN.md)。本说明写用户结果，详细字段/接口由对应产品经理和研发人员按原规则展开；不以现有代码反推需求。

## 用户从哪里进入、怎样完成

入口：内部认证后的产品概览、用户旅程、饭局与供需、体验与留存、数据与定义五页。

1. 分析者选择日期及适用业务筛选，看到同一有效统计快照的指标与口径。
2. 从异常/饭局/申请或队列下钻伪名用户及相关事实，逐层返回保留查询。
3. 数据管理员按具体用户保存测试/员工分类，分别看到分类已接受与统计待更新。
4. 统计就绪后显式使用覆盖最新已接受分类的有效快照，页面/下钻/导出都绑定同一范围。
5. 授权人员导出当前聚合结果，能追溯snapshot、过滤条件和口径，不含私密原文。

## 必须保持的业务规则

- 本人出席优先，host只补缺，unknown不作absent；保留分子/分母与来源。
- 分类已接受不等于统计可用；Pending/Failed禁止旧统计继续下钻/导出，重试只重做统计不重复分类。
- 观察未成熟不算流失；产品问卷仅日期/用户分群生效，不受单场预算/区域等筛选，不与私评分混用。
- 410撤销快照后清旧缓存和导出票据，不能切回已撤销字节；服务端每次授权。
- 后台保持五页与既定中英、1440/1024/864/390适配，不新增财务、商家、客服或AI管理。

## 失败、返回与取消

- 401回原查询、403清受限内容、410换有效快照、429按等待时间、503保查询重试；错误共用恢复规则不逐页复制新需求。
- 分类未知先查原意图；409读最新版本后由本人重新确认，不按别人的更大revision推断本用户分类已生效。
- 无数据/缺来源/零分母/导出失败分别说明，不伪填0或显示下载成功。

## 版本范围与可观察验收

### D10 基础统计与追溯

范围与终点：概览、用户旅程、饭局供需三页共用统计口径与快照，每页单独任务。

前置需求版：D03、D04、D06。

- D10-AC01：手算fixture与三页指标/分母一致，缺失不冒称0，数据来源可追溯。
- D10-AC02：筛选/下钻/返回保持同一查询和快照；分析者权限不扩大。
- D10-AC03：每页四档布局、长表和键盘操作按冻结规格验证，现有PASS只按确切构建继承。

### D11 分类、快照与导出

范围与终点：数据与定义、分类回执恢复、统计刷新、快照撤销和聚合导出。

前置需求版：D10。

- D11-AC01：未知分类查原key，Accepted只重试统计，不重复classify，逐用户revision准确绑定。
- D11-AC02：Pending/Failed/未选有效Ready时不读旧统计；410清内容/票据，旧下载仍拒绝。
- D11-AC03：导出snapshot/filter/口径与页面一致且脱敏；与D09删除撤销联合验证。

### D12 体验与留存

范围与终点：体验与留存页，问卷/单场体验分离，成熟队列及更正/删除影响。

前置需求版：D06、D07、D10、D11。

- D12-AC01：观察期、分母及unknown与采集契约和手算一致，未成熟不作流失。
- D12-AC02：问卷按截至asOf最新版本及版本提交日期选入，不回捞旧答案。
- D12-AC03：D08纠错影响新快照、D09删除使旧导出拒读，各有定向证据。

## 依赖、职责与不做事项

模块交接：消费M03/M04/M06权威事实；M07供纠错/删除撤销事件，不由后台重写业务真源。

本模块不做：直接操作举报/删除个案、读取消息/申请留言/单方再约、原始个人全量导出、新分析平台。

最小测试前置：固定指标样本及新快照、内部角色、分类/worker失败控制、四档浏览器；无需为本地统计反复开通真实账号。

上述验收是需求条件，不是已经执行的结果。受控测试、实际浏览器/设备、真实服务及联合旅程分别记录；原要求中的真实门槛未齐必须保留阻塞。一次模块验收不代表发布批准。

## 设计和worker交付要求

设计只覆盖上述自然路径、关键恢复及现有共享规则，复用冻结稿，新增画板必须说明对应需求版和验收编号。开发任务只选择本版一条路径/页面/合同，不把本说明整份交给一个worker并要求自定范围。

接任务前读取[版本与工作包规则](../module-version-plan-2026-10-26.zh-CN.md)，登记需求包提交、Figma版本/节点、代码基线、唯一作者、允许文件和证据范围。现有实现、冻结稿与PASS由原负责人逐项核对继承；本需求包未完成该盘点，不宣称需要全部重做，也不宣称全模块已通过。
