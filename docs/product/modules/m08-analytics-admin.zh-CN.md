# M08 产品数据与管理后台需求说明

需求修订：r05｜状态：产品需求草稿。

## 为什么需要、谁使用

内部团队需要知道用户能否找到饭局、为什么未约成、是否真实见面和是否再次参加，同时能辨认统计缺失及观察期。

使用者：内部产品分析者、维护测试/员工分类的数据管理员。二者是后台使用者，不代表开发岗位。

本版适用端：管理后台Web。 产品背景、功能范围与产品角色见[整体MVP需求](../fancy-requirements-baseline.zh-CN.md)。

## 用户从哪里进入、怎样完成

入口：内部认证后的产品概览、用户旅程、饭局与供需、体验与留存、数据与定义五页。

1. 分析者选择日期及适用业务筛选，看到同一有效统计快照的指标与口径。
2. 从异常/饭局/申请或队列下钻伪名用户及相关事实，逐层返回保留查询。
3. 数据管理员按具体用户保存测试/员工分类，分别看到分类已接受与统计待更新。
4. 统计就绪后显式使用覆盖最新已接受分类的有效快照，页面/下钻/导出都绑定同一范围。
5. 授权人员导出当前聚合结果，能追溯snapshot、过滤条件和口径，不含私密原文。

## 必须保持的业务规则

- 本人出席优先，host只补缺，unknown不作absent；保留分子/分母与来源。
- 分类已接受不等于统计可用；Pending/Failed禁止旧统计继续下钻/导出，重试只重做统计不重复分类。
- 观察未成熟不算流失；产品问卷仅日期/用户分群生效，不受单场预算/区域等筛选，不与私评分混用。
- 410撤销快照后清旧缓存和导出票据，不能切回已撤销字节；服务端每次授权。
- 后台保持五页与既定中英、1440/1024/864/390适配，不新增财务、商家、客服或AI管理。

## 失败、返回与取消

- 401回原查询、403清受限内容、410换有效快照、429按等待时间、503保查询重试；错误共用恢复规则不逐页复制新需求。
- 分类未知先查原意图；409读最新版本后由本人重新确认，不按别人的更大revision推断本用户分类已生效。
- 无数据/缺来源/零分母/导出失败分别说明，不伪填0或显示下载成功。

## 版本范围与可观察验收

### D10 基础统计与追溯

范围与终点：概览、用户旅程、饭局供需三页共用统计口径与快照，每页单独任务。


- D10-AC01：内部用户看到的概览、旅程及饭局供需与权威事实一致，分子分母、缺失和来源可理解。
- D10-AC02：查询、下钻和返回保持同一筛选与有效快照，分析权限不扩大到私密原文。
- D10-AC03：三页在既定后台宽度与中英界面可使用，长表和键盘操作不会丢失字段或当前查询。

### D11 分类、快照与导出

范围与终点：数据与定义、分类回执恢复、统计刷新、快照撤销和聚合导出。


- D11-AC01：分类未知时找回原次结果；分类已接受只重试统计，不重复保存，不拿其他人的版本冒充本人的结果。
- D11-AC02：统计未就绪或失败不继续展示旧统计；快照撤销后清内容及旧导出，不能读取旧下载。
- D11-AC03：导出与当前页面的有效快照、筛选和口径一致且脱敏；账号删除后的旧导出同样不可用。

### D12 体验与留存

范围与终点：体验与留存页，问卷/单场体验分离，成熟队列及更正/删除影响。


- D12-AC01：成熟观察窗口、未知状态、分母与口径一致，尚在观察的人不算流失。
- D12-AC02：产品问卷按指定时点的最新答案及该答案提交日期入组，不回捞旧答案，也不当作单场评分。
- D12-AC03：纠错影响新的统计结果，删除后的数据按撤销规则处理，原快照不被悄悄改写。

## 相关功能与范围边界

饭局、申请、出席和支持处理的业务事实分别来自M03/M04/M06/M07，后台不重新判定这些事实。

本模块不做：举报/删除个案写操作，读取消息/申请留言/单方再约，个人原始数据全量导出及新分析平台。

以上描述预期产品行为，不表示功能已实现或已经验收。
