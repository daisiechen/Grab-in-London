# M05 基础Inbox与授权聊天需求说明

需求包修订：r02｜文档性质：项目协调负责人的模块需求输入｜状态：待用户审阅，未签发实施工作包。

## 为什么需要、谁使用

获准同桌的人需要讨论见面安排；用户也需要看到申请与审批等进度，并在离群后理解还能读什么。

使用者及职责：已登录用户、当前群成员、历史成员、发起人；私聊双方权限由M06提供。

适用端：移动Web与iOS。背景、术语、规则权威及授权见[整体需求基线](../fancy-requirements-baseline.zh-CN.md)。本说明写用户结果，详细字段/接口由对应产品经理和研发人员按原规则展开；不以现有代码反推需求。

## 用户从哪里进入、怎样完成

入口：Inbox中的业务通知/会话、已获准饭局详情的Open group chat、授权私聊入口。

1. 用户从Inbox查看待审/获准等既有业务记录，打开对应饭局或有权限会话。
2. 群成员阅读消息、输入自己的文字并主动发送，另一端获得新消息。
3. 只把本机实际呈现且可见的消息位置记作聊天已读；通知列表已读单独操作。
4. 用户明确选择并确认退群；发起人可明确确认解散群聊，两者均不修改席位。
5. 退群/解散后保留授权区间历史只读入口；重新获准入群只开放新的授权区间。

## 必须保持的业务规则

- 首次批准即入群，Pending及从未入群用户无群历史读取权；退席不自动退群。
- 饭局结束/取消或外订失败不自动令群只读；主动退群与解散才按规则撤写权限。
- 退群空档消息不可读，重入不补全空档；解散群不重新开放。
- M06决定私聊是否能写，M05执行每次读取/发送鉴权及历史传输，不推断互选。

## 失败、返回与取消

- 断网发送失败保留原文与明确重试；权限撤回后停止排队重试，仍保留可复制/删除的未发文字。
- 群读取403进入本人有权只读历史或明确不可访问，不继续拉实时名册。
- 会话失效先清账号内存，迟到发送/轮询不污染新账号；同步失败不显示消息已送达。

## 版本范围与可观察验收

### D05 基础沟通闭环

范围与终点：两端正常消息往返、既有业务记录正确、离群只读且旧发送停止。

前置需求版：D04。

- D05-AC01：同库两端正常申请批准后发收消息，Pending账号访问被拒。
- D05-AC02：退席保留群、退群不改席位、解散不可发、重入只读历次授权区间。
- D05-AC03：断网保稿、401停止旧重试、403授权历史、可见已读与通知已读独立有实际结果。

## 依赖、职责与不做事项

模块交接：M11消费同一消息/成员权限，M12消费稳定提醒事件；M06提供私聊授权，M07可撤权。

本模块不做：@实体、免打扰、系统推送、在线状态/presence、替用户生成消息。

最小测试前置：同库两端账号、可控离线与会话失效、历史授权区间数据；不依赖AI或真实push。

上述验收是需求条件，不是已经执行的结果。受控测试、实际浏览器/设备、真实服务及联合旅程分别记录；原要求中的真实门槛未齐必须保留阻塞。一次模块验收不代表发布批准。
