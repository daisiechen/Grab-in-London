# M05 基础Inbox与授权聊天需求说明

需求修订：r03｜状态：产品需求草稿。

## 为什么需要、谁使用

获准同桌的人需要讨论见面安排；用户也需要看到申请与审批等进度，并在离群后理解还能读什么。

使用者：当前群成员、已经退出的历史成员、发起人，以及有共同联系资格的私聊双方。

本版适用端：iOS App。 产品背景、功能范围与产品角色见[整体MVP需求](../fancy-requirements-baseline.zh-CN.md)。

## 用户从哪里进入、怎样完成

入口：Inbox中的业务通知/会话、已获准饭局详情的Open group chat、授权私聊入口。

1. 用户从Inbox查看待审/获准等既有业务记录，打开对应饭局或有权限会话。
2. 群成员阅读消息、输入自己的文字并主动发送，另一成员在iOS App中获得新消息。
3. 只把本机实际呈现且可见的消息位置记作聊天已读；通知列表已读单独操作。
4. 用户明确选择并确认退群；发起人可明确确认解散群聊，两者均不修改席位。
5. 退群/解散后保留授权区间历史只读入口；重新获准入群只开放新的授权区间。

## 必须保持的业务规则

- 首次批准即入群，Pending及从未入群用户无群历史读取权；退席不自动退群。
- 饭局结束/取消或外订失败不自动令群只读；主动退群与解散才按规则撤写权限。
- 退群空档消息不可读，重入不补全空档；解散群不重新开放。
- M06决定私聊是否能写，M05执行每次读取/发送鉴权及历史传输，不推断互选。

## 失败、返回与取消

- 断网发送失败保留原文与明确重试；权限撤回后停止排队重试，仍保留可复制/删除的未发文字。
- 群读取403进入本人有权只读历史或明确不可访问，不继续拉实时名册。
- 会话失效先清账号内存，迟到发送/轮询不污染新账号；同步失败不显示消息已送达。

## 版本范围与可观察验收

### D05 基础沟通闭环

范围与终点：不同登录会话正常消息往返、既有业务记录正确、离群只读且旧发送停止。


- D05-AC01：获准成员可以在iOS中收发消息和查看既有业务通知；待审者不能读取群消息。
- D05-AC02：退席保留群身份，退群不改变席位，解散后不可发言；重新入群也看不到退出空档消息。
- D05-AC03：断网时未发送文字保留；失权后不继续发送，聊天实际可见位置与通知已读分别处理。

## 相关功能与范围边界

私聊资格由M06互选决定；提及与免打扰见M11，系统通知见M12。

本模块不做：提及实体、免打扰、系统通知与自动生成消息；这些分别属于其他模块。

以上描述预期产品行为，不表示功能已实现或已经验收。
