# QA 验收与回归

## 输入与范围
读取适用项目规则、权威需求、验收标准和现有测试入口。记录被测提交、未提交改动、运行环境、浏览器及测试数据。
明确本轮是测试计划、只读验收，还是允许新增测试。写入权限以用户授权和文件负责人约定为准。
需求不明确时记录待确认项；不根据当前实现反推正确需求。

## 测试矩阵
建立「需求编号 → 场景编号 → 预期结果 → 测试方式 → 证据 → 状态」映射。
按业务影响和变更风险选择核心路径、角色权限、边界输入、空状态、异常反馈、返回取消、刷新恢复、重复操作、跨模块一致性，以及受影响的布局、键盘操作和可访问性。
区分真实服务、受控 mock 和 Demo 模拟。对不适用项目说明原因，不机械扩大范围。

## 执行与取证
检查仓库实际配置，复用已有测试工具和启动入口。确认服务对应预期版本；只清理自己启动的进程。
按风险组合领域逻辑、接口契约、浏览器端到端测试和人工探索。
浏览器操作依据实际 DOM 或页面快照；优先使用 role、label 和稳定测试标识。等待具体业务状态与可重试断言，避免固定睡眠，不把 networkidle 当作通用就绪条件。
隔离测试数据、会话、时间等影响结果的状态。
关键场景保存步骤、断言和必要截图；失败时补充 trace、console 或 network 证据，清除敏感信息。截图不能单独证明功能正确。
明确标记 mock、未接入服务和工具能力限制。真实集成结论必须来自对应环境的实际验证。

## 缺陷与回归
为问题分配稳定编号，记录版本环境、前置数据、最小复现步骤、预期与实际结果、影响、严重程度、证据、建议负责人及关闭条件。严重程度与修复优先级分别记录。
区分产品缺陷、测试脚本缺陷、环境故障和需求歧义。
不通过删除断言、跳过用例、扩大超时或更新截图掩盖产品问题。修改预期需要需求依据。
按职责将问题交给产物负责人；修复后重跑原复现场景及受影响回归。重试通过仍保留首次失败记录并标注不稳定性。
需要验证回归用例能捕获旧缺陷时，使用隔离副本或历史版本；不回滚共享工作区。

## 验收报告
逐项报告 PASS、FAIL、BLOCKED、NOT RUN 或 N/A，并记录命令、执行时间、退出码、结果数量及证据位置。
给出通过、不通过或无法判定的结论，明确覆盖范围、未测内容和遗留风险。
构建通过不等于功能验收通过；测试通过不等于需求已批准或可以发布。
被测版本变化后重新评估受影响证据。无法执行的验证标注阻塞，不以推测代替结果。

## 技能验证
使用需求歧义、明确缺陷、修复后复验三个场景检查：能否保留未知、输出可复现报告、遵守写入职责并限定结论范围。
技能格式与引用检查通过只证明配置有效，不证明实际 QA 任务已完成。
